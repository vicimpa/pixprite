# Layer FX

Open **Layer → Layer FX…**, the command palette's `layer.effects`, or **FX** in the timeline. Add opacity, Outline, Drop Shadow, Glow or Color Overlay processors, edit their parameters, enable/disable them, delete them, and move them up/down. The stack runs from top to bottom: opacity before Outline differs from opacity after it. Consecutive opacity processors multiply alpha and round once, retaining older files’ appearance. [Outline](outline.md) documents exact pixel geometry, color/alpha, positions and corners. The **Add inner outline** preset adds the same Outline processor with position `inside`; its geometry and controls remain shared. Masks belong to a subsequent plan block.

The live preview uses the same renderer on the canvas, onion frames, animation playback and the preview window. **Play preview** runs the animation while the dialog is open. **Preview** compares the draft with the committed stack; **Apply** saves the stack in one undo step. Escape, Cancel and closing the window discard the draft, restore the opening frame/playback state, and leave the undo history and original images untouched. A draft neither marks the document dirty nor enters autosave/export captures. Close the modal to paint; drawing then edits source pixels and live FX update automatically.

## Baking and scope

**Bake effects** accepts the draft and bakes the entire stack in one undo step, without a separate Apply step. Choose the entire active layer, the frame that was current when the dialog opened, or the selected timeline frame range. Timeline layer selections do not make a frame range. Existing pixel selection masks do not limit a layer FX bake.

Only selected frame pixels are processed. Unselected cels keep their image resources, positions, instance transforms and continuous links. Selected linked cels share one result when their source and residual stack agree; links across the baked/unbaked boundary split. Per-frame and outer layer opacity, blend and clipping continue to apply once. Baking does not trim fully transparent images or discard off-canvas pixels.

After a partial bake, existing effects are skipped in those frames: reordering, enabling, editing or deleting those effects cannot apply them again. Adding a new effect applies it to every frame, including baked frames. Baking all remaining frames removes the fully baked stack. Undo/redo restores pixels, scopes, image sharing and any structural conversion together.

Baked scope follows timeline content through frame insertion/duplication, moving, copying, removal and reversal, cel linking/duplication/moving, the timeline clipboard, layer copies and tween source selection. Empty/new imported cells start with live FX. Moving or clearing a cell clears the source scope so later new drawing receives FX. Copying a cell to another layer retains only skipped IDs present in that destination's stack; unrelated source-layer effects do not suppress destination effects.

Groups retain their hierarchy. Baking adds one normal raster child containing the selected frames' isolated group composite (including children and the group's FX). Original descendant cels and their old baked-scope markers are cleared only in those selected frames. Every other frame retains its original editable child cels and links. The group still applies its outer opacity/blend/clipping once. Descendant layers can remain empty after a whole-group bake; deleting them is a separate user action. Locked descendants refuse group baking. Groups spanning more than 4096 × 4096 pixels refuse before allocation or mutation, with a visible dialog error; distant off-canvas content is included in that limit.

A tilemap bake converts the active tilemap layer to pixel cels for its whole timeline, retaining other frames' appearance and source image sharing. Tilesets and other layers remain available. Baking alpha or an enabled nontransparent color effect in an indexed document promotes it to RGB, preserving custom colors and arbitrary alpha instead of quantizing them to palette entries. Baking a background's alpha turns that layer into a regular pixel layer. The dialog describes group/tilemap/indexed conversions before baking.

## File and export representation

`.pixprite` v6 stores the editable stack in `layer.effects`: opacity entries are `{ id, type: "opacity", enabled, amount }`, with stable unique IDs and amounts in 0…1. Outline entries are `{ id, type: "outline", enabled, color, thickness, position, join }`: `color` is an unsigned packed RGBA pixel, `thickness` is an integer 1…128, `position` is `inside|center|outside`, and `join` is `round|miter|bevel`. Unknown discriminants and malformed parameters are rejected before pixel decoding. v6 already rejects unknown effect types, so adding Outline needs no version bump. There are at most 64 effects per layer. Image resources retain their original pixels until baking or painting. Enabled nontransparent color effects also promote grayscale baking/Aseprite export to RGB to retain color; opacity-only grayscale stays grayscale.

Optional `layer.bakedEffects` is a frame-count-sized array of string arrays. Each row lists effect IDs already baked into that frame. The renderer evaluates `effects` in stored order, excluding IDs in that row. Empty/absent rows mean the whole stack is live. IDs can be retained after an effect is removed; they are harmless and are normalized when baking again. The loader validates shape, frame count, unique IDs, string/length bounds before replacing the current document. Explicit v3 → v4 → v5 → v6 migrations retain older files and v5 live FX; old v5 applications refuse v6 files before reading unknown residual semantics. Declaring residual scope in a v5 file is rejected. The resource storage envelope stays at its existing internal version; immutable images and history accounting retain the existing policies.

PNG, GIF, video, sprite sheets and all image export paths use the shared renderer in Worker and fallback preparation, so they include committed residual FX once. PNG/video preparation retain RGBA; GIF keeps its existing binary transparency and palette limits. `.aseprite` export bakes pixel-layer effects into cels. Groups with active FX are flattened only in the exported copy into isolated pixel layers, preserving their outer opacity/blend/clipping and frame appearance. The editable `.pixprite` group/stack is unchanged. Indexed exports requiring arbitrary colors or alpha use RGB. Unapplied dialog previews are excluded from exports.

Verification: deterministic model/pixel tests cover preview isolation, scope/links, one-step undo/redo, group blending/clipping, clipboard and timeline edits, indexed/tilemap conversions, bounds refusal, validated loading, Worker captures and Aseprite/GIF/video preparation. The production Chromium scenario operates the actual FX controls, checks canvas preview/cancel and playback, saves stack order/enabled state, bakes one frame, undoes/redoes, exports exact PNG pixels and reloads.

Output bounds include cumulative outward growth and child FX. Explicit preview/Apply/Bake and Aseprite export refuse oversized geometry. Later source edits can temporarily pause an oversized stack, with a localized canvas alert; source pixels and enabled settings remain saveable and reloadable. PNG/GIF/video match the bounded live fallback, and processing resumes after geometry shrinks. See [Outline bounds and performance](outline.md#bounds-and-performance).


## Drop Shadow, Glow and Color Overlay

All color controls use packed unsigned RGBA (`0xAABBGGRR`) and an alpha byte 0–255. An effect with color alpha 0 is an identity: it neither grows the rectangle, separates consecutive opacity runs, nor promotes indexed/grayscale bake/export. Disabled processors are identities too. These effects participate in the same preview, Apply/Cancel, ordering, per-frame residual scopes, one-step baking, groups, clipping, blending and export paths described above. Source cels and Image resources remain untouched until painting or baking.

| Processor | Stored parameters | Geometry |
| --- | --- | --- |
| Drop Shadow | `type: "shadow", color, x, y, size` | Integer X/Y −1024…1024; positive Y is downward. Integer size 0…128 is a square box-blur radius. |
| Glow | `type: "glow", color, size, position` | Integer size 1…128; `position: "inside"` or `"outside"`; Euclidean falloff. |
| Color Overlay | `type: "overlay", color` | Recolors existing nontransparent pixels, preserving each alpha byte. |
| Inner Outline preset | `type: "outline", color, thickness, position: "inside", join` | The existing Outline inward geometry, including holes and exterior edges; no separate processor or duplicate algorithm. |

Drop Shadow offsets the previous processor's alpha and convolves it with a uniform `(2*size+1)²` kernel. Space beyond the bitmap is transparent, and normalization always uses that full kernel, including at edges. Size 0 is a hard shifted copy of alpha. The resulting alpha is multiplied by the shadow color alpha and rounded to a byte once; RGB comes from the shadow color. The original source is then composited source-over in front of the shadow. Thus semitransparent source pixels cast proportionally weaker shadows and can show shadow underneath. Hidden RGB in transparent source pixels casts nothing. The rectangle is the union of the source and its shifted rectangle expanded by `size` on all sides; positive and negative offsets are retained off-canvas.

Glow uses the existing exact Euclidean distance transform. A pixel belongs to the silhouette if alpha > 0. For an outside glow, distance `d` is measured to the nearest nontransparent pixel; coverage is `min(1, (size+1-d)/size)` when `d <= size`, otherwise zero. Boundary neighbours at distance 1 receive full color alpha; the ring at distance `size` receives `1/size`. The source is composited in front of this colored underlay, including underneath its semitransparent pixels. The rectangle grows by `size` on all sides. For an inside glow, distance is measured to the nearest transparent pixel, including exterior space and holes. The same coverage recolors RGB source-atop, retaining the exact source alpha; the rectangle does not grow. There is no antialiasing. An entirely transparent image remains transparent.

Color Overlay interpolates each RGB channel by `colorAlpha/255` with a single channel rounding, keeping source alpha. Fully opaque overlay color therefore replaces RGB throughout the silhouette, including semitransparent pixels; transparent pixels stay transparent. Ordering matters: an overlay after a shadow/glow recolors those added pixels, while an overlay before it only changes the incoming source.

Shadow uses two separable sliding-sum passes over alpha; Glow reuses the Outline distance transform. Both use O(output area) time and memory, independent of radius squared. Parameter validation precedes output allocation. The existing 4096-per-side / 16,777,216-pixel bounds and pause/resume policy cover all new processors and cumulative growth. Native Chromium checks exact soft-shadow PNG pixels and real paint/erase updates, all new controls, order, cancellation, baking, undo and reload; model tests additionally cover alpha/falloff, color modes, linked transformed sources, group clipping/blend, worker captures and exports.

## Persistent Lock Alpha

Enable **Lock Alpha** in **Layer properties**. Optional `layer.lockAlpha: boolean` defaults to false and belongs to that individual pixel/tilemap layer; groups do not impose it on their descendants. It is saved in `.pixprite`, copied with layers, validated on load and API updates, and restored by property undo/redo. Extensions read it in `LayerInfo.lockAlpha` and set it through `sprite.layers.update(index, { lockAlpha: true })`.

Pencil, eraser, shapes, custom brushes, spray/blur/scatter, flood fill, gradient, selection fill/clear, pixel filters and extension `putPixels` preserve the pre-edit alpha at every pixel. Opaque painting cannot add pixels outside the silhouette. RGB can change on existing pixels, while fully transparent/erasing results keep their original RGB too: a normal eraser is a no-op, rather than leaving black pixels. Transparent-key indexed quantization cannot erase a locked pixel; grayscale and tilemap edits use the same guard. Selection masks, ordinary/background locks, stroke cancellation, linked-cel sharing and immutable Image copy-on-write retain their normal behavior. Canvas painting retains off-canvas source pixels.

Lock Alpha controls pixel editing. Explicit structural operations—moving/transforming a cel or selection, pasting/importing content, resizing, tile/tileset structure changes, and baking FX—can change the silhouette; new layers have Lock Alpha off. Selection transforms cut and move normally even on an alpha-locked layer, and cancel/undo restores their original pixels. The flag does not clip the visible output of non-destructive effects.

The file version remains 6. New effect discriminants are already rejected by earlier v6 readers before decoding, so they cannot silently flatten or discard an unknown stack. `lockAlpha` is an optional editing restriction with a false default, not a new rendering or image-resource interpretation; absence in older files does not change their appearance or editing behavior. Load validates its boolean type before replacing the document. A pre-feature application may ignore this editing restriction; use the current editor to retain alpha-lock behavior.
