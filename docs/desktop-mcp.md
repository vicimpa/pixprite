# Настольное приложение и MCP

Pixprite использует **Tauri 2**, Rust и системный WebView: WKWebView на macOS, WebView2 на Windows и WebKitGTK на Linux. Chromium и Node.js в приложение не включаются. React-редактор сохраняется: один JS-бандл, отдельный вычислительный Worker и анимация запуска. Встроенные ресурсы открываются без локального веб-сервера через протокол Tauri; HTTP на loopback служит только MCP.

## Запуск и сборка

Нужны Bun 1.4.2 и Rust из `rust-toolchain.toml`. Для работы установленного редактора и MCP не нужны Node.js или Bun. Для macOS установите Xcode Command Line Tools; для Windows — Visual Studio C++ Build Tools и WebView2. Linux требует зависимости WebKitGTK 4.1; точный список приведён в [workflow](../.github/workflows/desktop.yml). См. также [требования Tauri](https://v2.tauri.app/start/prerequisites/).

```sh
bun install --frozen-lockfile
bun run desktop:dev
```

| Команда | Результат |
| --- | --- |
| `bun run desktop:dev` | Собрать веб-интерфейс и debug binary, запустить редактор |
| `bun run desktop:compile` | Пересобрать debug binary из готового `dist/web` |
| `bun run desktop:prepare` | Подготовить JS-мост и MCP без компиляции Rust |
| `bun run desktop:pack` | Release executable без установщика |
| `bun run desktop:build` | Release executable и установщики для текущей ОС |

Все release-сборки, включая публикацию в CI, используют профиль из `src-tauri/Cargo.toml`: оптимизацию размера (`opt-level = "z"`), полный LTO, одну единицу генерации кода и удаление символов. При Rust panic процесс завершается (`panic = "abort"`); обычные ошибки по-прежнему обрабатываются через `Result`. Debug-сборки сохраняют стандартный профиль Cargo.

Native-исходники находятся в `src-tauri/`, JS-мост и исходный каталог инструментов — в `desktop/`; HTTP MCP реализован в Rust и вызывает команды редактора напрямую. `dist/desktop/` содержит executable, metadata, каталог инструментов и подготовленный `web/`; `dist/tauri/` — Cargo output и нативные bundle; `dist/installers/` — установщики. Для сборки отдельных установщиков macOS под Apple Silicon и Intel:

```sh
bun run build
rustup target add aarch64-apple-darwin x86_64-apple-darwin
bun scripts/build-desktop.ts --target aarch64-apple-darwin
bun scripts/build-desktop.ts --target x86_64-apple-darwin
```

CI собирает macOS arm64 (Apple Silicon) и x64 (Intel) отдельными заданиями на соответствующих процессорах, Windows x64 (NSIS `.exe`, MSI) и Linux x64 (`.AppImage`, `.deb`). Для macOS публикуются два установщика: `Pixprite-<version>-mac-arm64.dmg` и `Pixprite-<version>-mac-x64.dmg`; `.app` каждой архитектуры остаётся в её каталоге Tauri bundle. Workflow проверяет приложение и native E2E на каждой архитектуре, сохраняет артефакты; при push тега `v*` публикует GitHub Release с MCP и SHA256SUMS. Тег должен совпадать с `package.json`. Сертификаты подписи и macOS notarization пока не настроены.

## Окно, файлы и хранилище

Единственное окно использует заголовок Pixprite и кнопки слева на macOS, справа на Windows/Linux. Свободная область перемещает окно; двойной щелчок разворачивает его. Вкладки переставляются внутри строки, отделения вкладок нет. Меню находится только внутри редактора; автоматическое меню Tauri на macOS отключено. Сочетания клавиш текстовых полей используют стандартную цепочку responder на macOS, включая изолированные панели расширений. Буфер изображений и сохранение экспортов обслуживаются нативно.

Если системный WebView не предоставляет WebGL2, цветовые градиенты рисуются через Canvas 2D. Это позволяет редактору запускаться и восстанавливать документы в виртуальных машинах и окружениях без ускорения GPU. Необработанные ошибки JavaScript передаются в stderr нативного процесса; native E2E проверяет их отсутствие, а CI сохраняет отчёты при сбое.

Файловые ассоциации заданы в `src-tauri/tauri.conf.json`. macOS передаёт файлы событием открытия, Windows/Linux — аргументами запуска; повторный запуск фокусирует имеющееся окно. Файлы открываются после восстановления сессии. Повторный запуск передаёт файлы в уже открытый редактор и показывает его окно. Новые окна не создаются; документы открываются во вкладках. При закрытии и выходе сохраняются рабочие копии всех вкладок. Сессии прежних многооконных сборок объединяются в одну с сохранением документов. Экспорт вызывает системный диалог сохранения.

Проекты хранятся обычными `.pixprite`-файлами: `~/Library/Application Support/Pixprite/Projects` на macOS, `%LOCALAPPDATA%\Pixprite\Projects` на Windows и `${XDG_DATA_HOME:-~/.local/share}/Pixprite/Projects` на Linux. Рабочие копии и снимки находятся в отдельных каталогах. Кнопка на Home открывает папку данных. Прежняя IndexedDB переносится автоматически и остаётся резервным источником; подробности — [хранилище и резервные копии](storage-and-backups.md).

Профиль оболочки и WebView остаётся прежним: `Pixprite/Tauri` в каталоге данных ОС (на Linux — конфигурации). `window.json` хранит настройки окна и ссылки на вкладки; общие предпочтения и расширения остаются в WebView. Веб-версия, Electron и Tauri используют разные хранилища. Перенос отдельного документа выполняется через `.pixprite`.

### Перенос профиля Electron

До первого запуска Tauri можно перенести проекты, рабочие копии, резервные записи и настройки из установленной Electron-версии. Закройте обе копии и укажите **старый executable**:

```sh
bun run desktop:migrate --electron /Applications/Pixprite.app/Contents/MacOS/Pixprite
```

Необязательные `--source /old/profile` и `--destination /new/profile` задают каталоги профилей. Скрипт копирует старый профиль во временный каталог, запускает старое приложение на этой копии через Playwright, сохраняет сессию и создаёт приватный `electron-migration.json` в новом профиле. При старте Tauri импортирует его до инициализации редактора. После подтверждения файл остаётся как `.imported.json`; исходный Electron-профиль не меняется и не удаляется. Повторный импорт того же backup безопасен. Существующая база Tauri или уже перенесённая файловая библиотека блокирует импорт, чтобы не перезаписать проекты; в этом случае переносите файлы `.pixprite`. Backup ограничен 256 MiB. Старые идентификаторы окон из backup объединяются при восстановлении в единственное окно.

## Уведомления о новых версиях

Запуск не ждёт сети. Через 10 секунд после готовности редактора оболочка проверяет последний опубликованный стабильный GitHub Release, затем повторяет проверку каждые 30 минут. Если версия новее установленной, сверху появляется компактное уведомление поверх интерфейса. Оно не занимает строку и не меняет высоту редактора. «Открыть релиз» открывает страницу выпуска в браузере; крестик скрывает уведомление в текущем окне. При появлении следующей версии уведомление появляется снова.

Редактор ничего не скачивает, не заменяет содержимое и не перезапускается. Установка новой версии выполняется пользователем через обычный установщик. Проверки офлайн, ошибки сети и лимиты GitHub остаются незаметными; уже показанное уведомление при ошибке проверки сохраняется. Draft, prerelease, текущие и старые версии не вызывают уведомление. Старый кэш обновлений больше не используется и не изменяется.

Проверяется только JSON из GitHub API `repos/vicimpa/pixprite/releases/latest`: стабильная semver, лимит ответа 256 KiB, таймаут 20 секунд. URL релиза строится из проверенной версии и доверенного адреса репозитория. Свой manifest, content ZIP, runtime fingerprint и отдельное обновление оболочки больше не нужны. PWA продолжает обновляться Service Worker.

`PIXPRITE_UPDATE_URL=http://127.0.0.1:<port>/latest` задаёт QA endpoint с JSON вида `{"tag_name":"v0.0.3","draft":false,"prerelease":false}`. `PIXPRITE_DISABLE_UPDATES=1` отключает сетевую проверку. В debug-сборках проверка отключена без явного endpoint.

## Подключение MCP

По умолчанию MCP выключен: обычный запуск редактора не открывает порт и не создаёт серверный процесс. Откройте **Правка → Настройки MCP…** (на главной — **Файл → Настройки MCP…**) или постоянную кнопку **Настройки MCP** внизу общих настроек. **Запускать MCP автоматически** сохраняет выбор в профиле. Порт по умолчанию — `3356`; `0` выбирает свободный порт. Сохранённый порт применяется при следующем включении MCP.

Для включения только на время текущего запуска:

```sh
pixprite --mcp
pixprite --mcp --mcp-port 4321
pixprite --no-mcp
```

`--no-mcp` принудительно отключает MCP, даже если автозапуск сохранён в настройках. Флаг полезен для тестов без MCP и не меняет сохранённое предпочтение. Одновременное указание `--mcp` и `--no-mcp` считается ошибкой. Повторный запуск с `--no-mcp` также отключает сервер в уже открытом редакторе.

`--mcp`, `--no-mcp` и `--mcp-port` не записывают настройки. `--mcp-port` требует `--mcp`; допустимы значения `0…65535`, включая форму `--mcp-port=4321`. В панели видно, когда MCP принудительно включён флагом. Если MCP уже работает на другом порту, повторный запуск сохраняет существующий сервер, а панель сообщает, что запрошенный порт не применён.

### Один редактор и встроенный сервер

MCP работает прямо в процессе редактора на Rust: HTTP-запросы передаются в существующий мост Tauri. Дочерний процесс, WebSocket-соединения между процессами, heartbeat и ожидание завершения не используются. PID из файла подключения совпадает с PID приложения.

Приложение поддерживает одно окно. Повторный запуск с файлами открывает их вкладками в уже работающем редакторе, сохраняя текущие несохранённые правки. Повторный запуск без файлов показывает существующее окно. Пункта «Новое окно» и маршрутизации MCP по `windowId` нет: сервер всегда работает с текущим редактором.

При отключении MCP или закрытии окна сервер сразу закрывает порт и удаляет принадлежащий ему файл подключения. На macOS сам GUI-процесс может оставаться в Dock; повторное открытие восстанавливает то же единственное окно и запускает MCP, если этого требует настройка или флаг текущего запуска.

### Конфигурация клиента

Сервер использует [Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) и официальный [Rust SDK MCP](https://github.com/modelcontextprotocol/rust-sdk). Endpoint — `http://127.0.0.1:<port>/mcp`. Скопируйте готовую JSON-конфигурацию из панели в MCP-настройки ассистента:

```json
{
  "mcpServers": {
    "pixprite": {
      "url": "http://127.0.0.1:3356/mcp",
      "headers": {
        "Authorization": "Bearer <токен из панели>"
      }
    }
  }
}
```

Node.js, Bun и внешний stdio launcher не требуются. JSON содержит токен доступа; храните его в настройках своего клиента. Токен сохраняется в приватном профиле и остаётся действительным после перезапуска сервера. Заголовки `Host` и `Origin` проверяются, сервер слушает только `127.0.0.1`.

`~/.pixprite/connection.json` содержит адреса, PID сервера и приватные данные локального соединения, права — `0600` на Unix. `PIXPRITE_CONNECTION_FILE` меняет путь discovery, `PIXPRITE_USER_DATA` изолирует профиль. Для изолированных тестов задавайте обе переменные. `mcp-token.json` находится в каталоге профиля. Для MCP используется один токен доступа; отдельного соединения окон с сервером нет.

В веб-версии сервер не запускается; панель объясняет, что требуется настольное приложение.

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `pixprite_documents` | Открытые документы, их ID и активная вкладка |
| `pixprite_library` | Сохранённые проекты и папки, включая закрытые: без `folderId` — вся библиотека, `null` — корень, ID — прямое содержимое папки; `filter` ищет по именам |
| `pixprite_open_project` | Открыть проект библиотеки по ID или переключиться на его вкладку с сохранением несохранённых правок |
| `pixprite_create`, `pixprite_select` | Создать документ или выбрать фоновую цель агента |
| `pixprite_open`, `pixprite_save` | Открыть локальный файл; записать `.pixprite`, `.aseprite`/`.ase` или PNG |
| `pixprite_inspect` | Размеры, палитра, слои, кадры, теги, slices, `documentId`, `revision`, playback и камера |
| `pixprite_preview` | Актуальный PNG текущего или выбранного кадра/слоя с `documentId`, `frame`, `layer`, `revision` |
| `pixprite_pixels` | Прочитать/записать RGBA base64 или залить прямоугольник hex-цветом |
| `pixprite_pixels_batch` | Атомарные read/write/fill на нескольких слоях и кадрах, один undo-шаг |
| `pixprite_playback` | Явные `play`, `pause` с сохранением кадра и `stop` с возвратом к кадру 0 |
| `pixprite_view` | Кадр, слой, zoom, pan в координатах спрайта, center/fit и onion skin одним вызовом |
| `pixprite_selection` | Нативный буфер выделения, вставка между документами, перенос, отражение и поворот на 90° без сглаживания |
| `pixprite_compare` | Контактный лист кадров/слоёв нескольких документов, наложение референса и направляющие; отдельная вкладка канваса только для просмотра |
| `pixprite_edit` | Пакет операций над слоями, кадрами, тегами, slices, палитрой и выделением |
| `pixprite_commands`, `pixprite_run_command` | Найти команды и их схемы аргументов, выполнить команду |
| `pixprite_analyze` | Границы занятых пикселей, центроид, частые цвета и пустые cels по слоям/кадрам |
| `pixprite_skills`, `pixprite_read_skill` | Общие для MCP и AI Assistant инструкции по изучению, рисованию, анимации и сравнению |
| `pixprite_get_selection` | Выделение агента и его небольшая маска |
| `pixprite_history` | Undo/redo |
| `pixprite_performance` | Ограниченный по времени замер частоты rAF, событий ввода/ресайза и длинных задач |

Например, создайте документ `16×16`, залейте прямоугольник `{x:4,y:4,w:8,h:8}` цветом `#ff6688ff`, запросите preview и сохраните в `/absolute/path/example.pixprite`. Все индексы слоёв и кадров начинаются с нуля. MCP возвращает ошибки инструментов через `isError`, а не выдаёт неудачную операцию за успешную.

Запись пикселей и документные операции используют существующую модель и проверки блокировок. `pixprite_edit` и `pixprite_pixels_batch` создают один undo-шаг и откатывают весь пакет при ошибке, включая вложенные структурные изменения. Пиксельный пакет выполняется синхронно: reads видят предыдущие writes, действия пользователя не вклиниваются между операциями. Пакет только из reads не создаёт undo-запись. Суммарный лимит пакета — 1 048 576 пикселей и 1024 операции.

MCP и AI Assistant используют один каталог `src/core/automation/catalog.ts` и один исполнитель `execute.ts`. В расширениях они доступны через `ctx.automation.list()` и `ctx.automation.call(name,args)`, поверх существующего RPC расширений. Отдельного JSON-протокола ассистента нет. Каталог фильтруется по разрешениям расширения; локальные файловые пути доступны только нативному адаптеру.

Команда `file.save` сохраняет выбранный документ в библиотеку без диалога, смены вкладки и нового undo-шага. Она доступна через общий каталог; адресация и проверка revision действуют так же, как для других операций. Открытие системных файловых диалогов через команды автоматизации не поддерживается.

Неквадратные пиксели доступны через `pixprite_run_command` с `id:"image.pixelRatio"` и `args:{x:2,y:1}`. Inspect возвращает `pixelRatioX/pixelRatioY`, размеры документа и координаты остаются логическими. Preview и compare применяют пропорции; Preview дополнительно возвращает `logicalWidth/logicalHeight`. PNG через `pixprite_save` сохраняет исходную сетку; `applyPixelRatio:true` запекает форму пикселя. `.pixprite` и `.aseprite` сохраняют метаданные без изменения пикселей.

`documentId` адресует открытый документ независимо от видимой вкладки. `pixprite_select` меняет цель агента, не фокусирует окно и не переключает пользователя. Если целевой документ закрыт, операция завершится ошибкой: перехода к случайной текущей вкладке нет. `contextId` разделяет параллельные задачи: у каждой свои документ, кадр, слой, выделение, камера, playback и внутренний буфер фрагментов. Копирование через автоматизацию не использует ни системный, ни пользовательский буфер редактора.

Перед изменениями изучите документ. Передавайте `expectedRevision` из inspect или последнего результата; без него исполнитель проверяет последнюю revision, прочитанную этим контекстом. Конфликт с ручной правкой требует перечитать документ и пересмотреть изменение. История пользователя также защищается от отмены по старому состоянию. После успешной записи используйте новую revision; номер растёт при undo/redo и может увеличиться более чем на один за пакет. При первом обращении без documentId/contextId цель берётся из текущего редактора и затем остаётся привязанной, пока агент явно не выберет другую.

Интерфейс не бегает за инструментами во время работы пользователя. После 10 секунд простоя он начинает показывать последний документ/кадр/область агента, только когда Pixprite видим и имеет фокус. Ввод в редакторе или панели расширения немедленно прекращает слежение и подсветку. Свёрнутое или фоновое окно не поднимается, рабочий стол и фокус других приложений не меняются. `follow:false` отключает визуальное слежение для вызова. AI Assistant использует тот же механизм; смена вкладки или переход на Home не останавливает текущий ответ.

```json
{
  "documentId": "<ID из inspect>",
  "expectedRevision": 42,
  "label": "Adjust walking poses",
  "operations": [
    {"action":"fill","layer":0,"frame":2,"rect":{"x":4,"y":4,"w":2,"h":2},"fill":"#ff6688ff"},
    {"action":"write","layer":1,"frame":3,"rect":{"x":4,"y":4,"w":1,"h":1},"data":"/2aI/w=="},
    {"action":"read","layer":1,"frame":3,"rect":{"x":4,"y":4,"w":1,"h":1}}
  ]
}
```

Preview сбрасывает сохранённые композиты и синхронно захватывает текущую модель до кодирования PNG; пауза после записи не нужна. Изображение остаётся первым content-блоком ответа MCP, метаданные идут следующим текстовым блоком и в `structuredContent`, без дублирования base64. Revision относится к захваченному изображению: пользователь может продолжать работу во время его кодирования.

`pixprite_view` устанавливает кадр, слой и камеру агента; курсор пользователя остаётся независимым. `zoom` — масштаб от 0.25 до 128, `pan:{x,y}` — точка спрайта в центре окна. `onion:{enabled,before,after,opacity}` управляет встроенной калькой. `pixprite_selection` использует личный буфер контекста агента без системного clipboard: задайте выделение через `sprite.selection.set`, выполните `copy`, переключите документ/кадр/слой и вызовите `paste`. `x`/`y` задают левый верхний угол результата; `flipX`, `flipY`, `turns` выполняют отражения и целые четверти оборота. Вставка и transform сразу фиксируются одним undo-шагом. Перед ними нужно завершить уже плавающее выделение.

`pixprite_compare` принимает `items:[{documentId,frame,layer?,expectedRevision?,reference?}]`, `columns`, общий целый `scale`, `guides:[{axis:"y",pos:12}]`. Reference задаётся как `{documentId,frame,layer?,expectedRevision?,opacity?,x?,y?}`. Все ячейки имеют одинаковый масштаб; метаданные содержат revision и координаты каждой ячейки. С `show:true` (по умолчанию) создаётся отдельная вкладка просмотра с настоящим канвасом и шахматным фоном. Она поддерживает zoom/pan, fit и закрытие, не принимает рисование, paste, undo и другие изменения спрайта, не входит в проекты или undo. Во время ввода вкладка не перехватывает показ; её можно выбрать вручную. `title` задаёт имя, ответ содержит `viewerId`. Для обновления снимка вызовите compare снова; `show:false` возвращает только ответ MCP. Общий размер ограничен 4096 px на сторону.

Файлы сохраняются через временный файл; существующий путь требует `overwrite: true`. Автоматизация не выполняет произвольный JavaScript. Playback и курсор агента независимы от пользовательских. Команда `anim.play` переключает playback своего контекста, pause/stop доступны во время воспроизведения. Незавершённый ручной штрих или плавающее выделение в целевом документе блокируют конфликтующую запись до завершения жеста. Автоматизация команд ограничена операциями над документом; системные диалоги, clipboard и команды других расширений в каталог не входят. Команды с формой параметров требуют `args`, чтобы не открывать диалог. Импорт ограничен 64 MiB на файл, отдельный pixel-запрос — 1 048 576 пикселями, preview — 4096 px на сторону.

В схеме `pixprite_edit` args опубликованы как обычный массив с типами элементов, без `prefixItems`, который некоторые клиенты неверно отображали как `string[]`. Передавайте числа, объекты и массивы непосредственно, а не строки с JSON. Позиции и значения аргументов строго проверяются общим исполнителем до транзакции.

Для изучения пикселей задавайте `encoding:"hex"`: чтение дополнительно вернёт `rows` с цветами. Запись принимает `rows` вместо base64, максимум 4096 пикселей, одинаковая длина строк; пустая строка стирает пиксель. `pixprite_analyze` принимает `layers`/`frames` и измеряет реальную альфу, bounds, centroid и частые RGBA-цвета. Измерения не распознают семантически голову или ноги. Загрузите подходящий навык через `pixprite_read_skill`: `inspect-sprite`, `draw-pixel-art`, `edit-sprite`, `animate-sprite`, `compare-poses`, `sprite-palette` или `editor-commands`.

## Проверка

```sh
bun run build
bun run desktop:compile
bun test desktop
bun run test:native
bun run test:desktop
bun scripts/check-desktop-package.ts
```

Native E2E запускают настоящий Tauri executable и подключаются по HTTP к MCP внутри этого же процесса. Проверяются выключенный по умолчанию MCP, флаги без изменения настроек, отдельный порт, повторное открытие файлов в одном окне, сохранение несохранённых правок и восстановление старых сессий. Проверяются MCP, пиксели с полупрозрачностью, undo/redo, атомарные операции, PNG, файлы, восстановление сессии, отсутствие системного меню и аутентификация loopback. Уведомления проверяются локальным endpoint: проверка после запуска, только JSON-запросы, отсутствие скачивания/перезапуска, сохранение уведомления при ошибке и игнорирование старых кэшей. Browser E2E проверяют всплывашку в обоих языках, её закрытие и отсутствие сдвига интерфейса.

`PIXPRITE_E2E_EXECUTABLE=/absolute/path/to/executable` проверяет упакованное приложение. На Linux нужен дисплей, например `xvfb-run -a bun run test:desktop`. Браузерные тесты запускаются отдельно через `bun run test:e2e` и не требуют Rust. Скрипт проверки пакета принимает каталог подготовленного содержимого и необязательный путь к executable; на macOS проверяет также отсутствие встроенных browser frameworks и отсутствие внешнего MCP launcher.

Нативные тесты по умолчанию запускают невидимые окна: они не появляются на экране, не получают фокус и не добавляются в панель задач. Работают настоящий WebView, вычислительный Worker и встроенный HTTP MCP; проверяются редактирование, PNG, файлы, сессии и повторный запуск без новых окон. В изолированном тестовом профиле включается `PIXPRITE_E2E_HIDDEN=1`, а фоновое торможение WebView отключается там, где это поддерживается. На macOS тестовое приложение не активируется и не показывается в Dock. Для ручной отладки с видимыми окнами: `PIXPRITE_E2E_SHOW_WINDOWS=1 bun run test:desktop`. Для замера времени запуска и завершения можно включить `PIXPRITE_E2E_TIMINGS=1`. Вёрстка и скриншоты дополнительно проверяются браузерными E2E в headless Chromium/WebKit.

Плавность перетаскиваний, настройка WebKit и измерения 60/120 Гц: [interface performance](interface-performance.md).
