# Настольное приложение и MCP

Pixprite использует **Tauri 2**, Rust и системный WebView: WKWebView на macOS, WebView2 на Windows и WebKitGTK на Linux. Chromium и Node.js в приложение не включаются. React-редактор сохраняется: один JS-бандл, отдельный вычислительный Worker и анимация запуска. Встроенные ресурсы открываются без локального веб-сервера через протокол Tauri; HTTP на loopback служит только MCP.

## Запуск и сборка

Нужны Bun 1.4.2 и Rust из `rust-toolchain.toml`. Node.js 24+ нужен внешнему stdio MCP-клиенту, а не самому редактору. Для macOS установите Xcode Command Line Tools; для Windows — Visual Studio C++ Build Tools и WebView2. Linux требует зависимости WebKitGTK 4.1; точный список приведён в [workflow](../.github/workflows/desktop.yml). См. также [требования Tauri](https://v2.tauri.app/start/prerequisites/).

```sh
bun install --frozen-lockfile
bun run desktop:dev
```

| Команда | Результат |
| --- | --- |
| `bun run desktop:dev` | Собрать веб-интерфейс и debug binary, запустить редактор |
| `bun run desktop:compile` | Пересобрать debug binary из готового `dist/web` |
| `bun run desktop:prepare` | Подготовить JS-мост и MCP без компиляции Rust |
| `bun run desktop:pack` | Release executable без установщика |
| `bun run desktop:build` | Release executable и установщики для текущей ОС |

Все release-сборки, включая публикацию в CI, используют профиль из `src-tauri/Cargo.toml`: оптимизацию размера (`opt-level = "z"`), полный LTO, одну единицу генерации кода и удаление символов. При Rust panic процесс завершается (`panic = "abort"`); обычные ошибки по-прежнему обрабатываются через `Result`. Debug-сборки сохраняют стандартный профиль Cargo.

Native-исходники находятся в `src-tauri/`, JS-мост и stdio MCP — в `desktop/`. `dist/desktop/` содержит executable, MCP, metadata и подготовленный `web/`; `dist/tauri/` — Cargo output и нативные bundle; `dist/installers/` — установщики. Для сборки отдельных установщиков macOS под Apple Silicon и Intel:

```sh
bun run build
rustup target add aarch64-apple-darwin x86_64-apple-darwin
bun scripts/build-desktop.ts --target aarch64-apple-darwin
bun scripts/build-desktop.ts --target x86_64-apple-darwin
```

CI собирает macOS arm64 (Apple Silicon) и x64 (Intel) отдельными заданиями на соответствующих процессорах, Windows x64 (NSIS `.exe`, MSI) и Linux x64 (`.AppImage`, `.deb`). Для macOS публикуются два установщика: `Pixprite-<version>-mac-arm64.dmg` и `Pixprite-<version>-mac-x64.dmg`; `.app` каждой архитектуры остаётся в её каталоге Tauri bundle. Workflow проверяет приложение и native E2E на каждой архитектуре, сохраняет артефакты; при push тега `v*` публикует GitHub Release с MCP и SHA256SUMS. Тег должен совпадать с `package.json`. Сертификаты подписи и macOS notarization пока не настроены.

## Окно, файлы и хранилище

Одно окно использует заголовок Pixprite и кнопки слева на macOS, справа на Windows/Linux. Свободная область перемещает окно; двойной щелчок разворачивает его. Вкладки переставляются внутри строки, отделения вкладок нет. Меню находится только внутри редактора; автоматическое меню Tauri на macOS отключено. Сочетания клавиш текстовых полей используют стандартную цепочку responder на macOS, включая изолированные панели расширений. Буфер изображений и сохранение экспортов обслуживаются нативно.

Если системный WebView не предоставляет WebGL2, цветовые градиенты рисуются через Canvas 2D. Это позволяет редактору запускаться и восстанавливать документы в виртуальных машинах и окружениях без ускорения GPU. Необработанные ошибки JavaScript передаются в stderr нативного процесса; native E2E проверяет их отсутствие, а CI сохраняет отчёты при сбое.

Файловые ассоциации заданы в `src-tauri/tauri.conf.json`. macOS передаёт файлы событием открытия, Windows/Linux — аргументами запуска; повторный запуск фокусирует имеющееся окно. Файлы открываются после восстановления сессии. При закрытии и выходе редактор сохраняет рабочие копии всех вкладок. Экспорт вызывает системный диалог сохранения.

Проекты хранятся обычными `.pixprite`-файлами: `~/Library/Application Support/Pixprite/Projects` на macOS, `%LOCALAPPDATA%\Pixprite\Projects` на Windows и `${XDG_DATA_HOME:-~/.local/share}/Pixprite/Projects` на Linux. Рабочие копии и снимки находятся в отдельных каталогах. Кнопка на Home открывает папку данных. Прежняя IndexedDB переносится автоматически и остаётся резервным источником; подробности — [хранилище и резервные копии](storage-and-backups.md).

Профиль оболочки и WebView остаётся прежним: `Pixprite/Tauri` в каталоге данных ОС (на Linux — конфигурации). `window.json` хранит настройки окна и ссылки на вкладки; общие предпочтения и расширения остаются в WebView. Веб-версия, Electron и Tauri используют разные хранилища. Перенос отдельного документа выполняется через `.pixprite`.

### Перенос профиля Electron

До первого запуска Tauri можно перенести проекты, рабочие копии, резервные записи и настройки из установленной Electron-версии. Закройте обе копии и укажите **старый executable**:

```sh
bun run desktop:migrate --electron /Applications/Pixprite.app/Contents/MacOS/Pixprite
```

Необязательные `--source /old/profile` и `--destination /new/profile` задают каталоги профилей. Скрипт копирует старый профиль во временный каталог, запускает старое приложение на этой копии через Playwright, сохраняет сессию и создаёт приватный `electron-migration.json` в новом профиле. При старте Tauri импортирует его до инициализации редактора. После подтверждения файл остаётся как `.imported.json`; исходный Electron-профиль не меняется и не удаляется. Повторный импорт того же backup безопасен. Существующая база Tauri или уже перенесённая файловая библиотека блокирует импорт, чтобы не перезаписать проекты; в этом случае переносите файлы `.pixprite`. Backup ограничен 256 MiB. Старые идентификаторы окон из backup объединяются при восстановлении в единственное окно.

## Уведомления о новых версиях

Запуск не ждёт сети. Через 10 секунд после готовности редактора оболочка проверяет последний опубликованный стабильный GitHub Release, затем повторяет проверку каждые 30 минут. Если версия новее установленной, сверху появляется компактное уведомление поверх интерфейса. Оно не занимает строку и не меняет высоту редактора. «Открыть релиз» открывает страницу выпуска в браузере; крестик скрывает уведомление в текущем окне. При появлении следующей версии уведомление появляется снова.

Редактор ничего не скачивает, не заменяет содержимое и не перезапускается. Установка новой версии выполняется пользователем через обычный установщик. Проверки офлайн, ошибки сети и лимиты GitHub остаются незаметными; уже показанное уведомление при ошибке проверки сохраняется. Draft, prerelease, текущие и старые версии не вызывают уведомление. Старый кэш обновлений больше не используется и не изменяется.

Проверяется только JSON из GitHub API `repos/vicimpa/pixprite/releases/latest`: стабильная semver, лимит ответа 256 KiB, таймаут 20 секунд. URL релиза строится из проверенной версии и доверенного адреса репозитория. Свой manifest, content ZIP, runtime fingerprint и отдельное обновление оболочки больше не нужны. PWA продолжает обновляться Service Worker.

`PIXPRITE_UPDATE_URL=http://127.0.0.1:<port>/latest` задаёт QA endpoint с JSON вида `{"tag_name":"v0.0.3","draft":false,"prerelease":false}`. `PIXPRITE_DISABLE_UPDATES=1` отключает сетевую проверку. В debug-сборках проверка отключена без явного endpoint.

## Подключение MCP

Сначала откройте настольный редактор. Его локальный мост создаёт `~/.pixprite/connection.json` с адресом `127.0.0.1` на случайном порту и токеном. Файл имеет права `0600` на Unix; токен не нужно копировать в конфигурацию клиента. Мост отклоняет браузерный `Origin`, неправильный Host и запросы без токена. Сайт/PWA этот мост не запускает.

`dist/desktop/mcp.mjs` — стабильный stdio launcher; для запуска требуется Node.js 24+. Он выбирает проверенный MCP payload запущенного приложения, а без запущенного приложения использует соседний `mcp-builtin.mjs`. Поэтому при копировании launcher нужно сохранять оба файла рядом. `pixprite-mcp.mjs` из GitHub Release — тот же launcher; скачивайте рядом с ним `mcp-builtin.mjs`. SDK уже включён в payload. В установленных приложениях launcher и встроенный fallback находятся рядом: `mcp.mjs` и `mcp-builtin.mjs` в каталоге ресурсов Tauri (`Pixprite.app/Contents/Resources/` на macOS). Активный MCP payload копируется из встроенных ресурсов приложения в userData и сверяется launcher по SHA-256. После обновления редактора новые MCP-подключения используют новые инструменты; уже открытый MCP-клиент нужно перезапустить для обновления списка инструментов. Launcher подключается к текущему открытому приложению; сам редактор не запускает.

Для Codex выполните из корня репозитория:

```sh
codex mcp add pixprite -- node "$PWD/dist/desktop/mcp.mjs"
```

Либо добавьте в конфигурацию клиента:

```toml
[mcp_servers.pixprite]
command = "node"
args = ["/absolute/path/to/pixprite/dist/desktop/mcp.mjs"]
tool_timeout_sec = 45
```

Формат и способы подключения описаны в [официальной документации Codex](https://developers.openai.com/codex/mcp/). После добавления перезапустите клиент/расширение, чтобы он загрузил новый сервер. В клиенте с JSON-конфигурацией stdio:

```json
{
  "mcpServers": {
    "pixprite": {
      "command": "node",
      "args": ["/absolute/path/to/pixprite/dist/desktop/mcp.mjs"]
    }
  }
}
```

Для отдельного профиля или теста можно задать `PIXPRITE_CONNECTION_FILE` и приложению, и MCP-серверу; сервер также принимает `--connection /absolute/path/connection.json`. `PIXPRITE_USER_DATA` изолирует профиль. На macOS отдельные WebView-хранилища для тестовых профилей требуют macOS 14+. stdout сервера содержит только MCP JSON-RPC, диагностика идёт в stderr.

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `pixprite_documents` | Открытые документы, их ID и активная вкладка |
| `pixprite_create`, `pixprite_select` | Создать документ или активировать вкладку |
| `pixprite_open`, `pixprite_save` | Открыть локальный файл; записать `.pixprite`, `.aseprite`/`.ase` или PNG |
| `pixprite_inspect` | Размеры, палитра, слои, кадры, теги, slices |
| `pixprite_preview` | PNG текущего или выбранного кадра в ответе MCP |
| `pixprite_pixels` | Прочитать/записать RGBA base64 или залить прямоугольник hex-цветом |
| `pixprite_edit` | Пакет операций над слоями, кадрами, тегами, slices, палитрой и выделением |
| `pixprite_commands`, `pixprite_run_command` | Найти команды и их схемы аргументов, выполнить команду |
| `pixprite_history` | Undo/redo |
| `pixprite_performance` | Ограниченный по времени замер частоты rAF, событий ввода/ресайза и длинных задач |

Например, создайте документ `16×16`, залейте прямоугольник `{x:4,y:4,w:8,h:8}` цветом `#ff6688ff`, запросите preview и сохраните в `/absolute/path/example.pixprite`. Все индексы слоёв и кадров начинаются с нуля. MCP возвращает ошибки инструментов через `isError`, а не выдаёт неудачную операцию за успешную.

Запись пикселей и документные операции используют существующую модель и проверки блокировок. `pixprite_edit` создаёт один undo-шаг и откатывает весь пакет при ошибке. Файлы сохраняются через временный файл; существующий путь требует `overwrite: true`. Автоматизация не выполняет произвольный JavaScript. Перед изменениями нужно закрыть модальные окна и остановить playback; команды с формой параметров требуют `args`, чтобы не открывать диалог. Импорт ограничен 64 MiB на файл, отдельный pixel-запрос — 1 048 576 пикселями, preview — 4096 px на сторону.

## Проверка

```sh
bun run build
bun run desktop:compile
bun test desktop
bun run test:native
bun run test:desktop
bun scripts/check-desktop-package.ts
```

Native E2E запускают настоящий Tauri executable и отдельный stdio Node-клиент. Проверяются MCP, пиксели с полупрозрачностью, undo/redo, атомарные операции, PNG, файлы, восстановление сессии, отсутствие системного меню и аутентификация loopback. Уведомления проверяются локальным endpoint: проверка после запуска, только JSON-запросы, отсутствие скачивания/перезапуска, сохранение уведомления при ошибке и игнорирование старых кэшей. Browser E2E проверяют всплывашку в обоих языках, её закрытие и отсутствие сдвига интерфейса.

`PIXPRITE_E2E_EXECUTABLE=/absolute/path/to/executable` проверяет упакованное приложение. На Linux нужен дисплей, например `xvfb-run -a bun run test:desktop`. Браузерные тесты запускаются отдельно через `bun run test:e2e` и не требуют Rust. Скрипт проверки пакета принимает каталог подготовленного содержимого и необязательный путь к executable; на macOS проверяет также отсутствие встроенных browser frameworks и наличие внешнего MCP.

Плавность перетаскиваний, настройка WebKit и измерения 60/120 Гц: [interface performance](interface-performance.md).
