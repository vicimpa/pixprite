# Совместимость `.aseprite`

Pixprite читает и записывает поддерживаемые данные `.aseprite`/`.ase`. Полная совместимость со всеми полями формата не заявляется. Структура бинарных файлов сверяется с [открытой спецификацией формата](https://github.com/aseprite/aseprite/blob/main/docs/ase-file-specs.md).

## Матрица поддержки

| Данные | Поддержка | Ограничения |
| --- | --- | --- |
| Размеры, пиксели RGB/grayscale/indexed, прозрачность | Поддерживаются | Действуют лимиты размеров и суммарных пикселей; RGBA индексированного документа хранится через палитру |
| Слои и группы | Поддерживаются | Порядок, вложенность, видимость, обычная блокировка, opacity и первые 16 режимов наложения; неизвестный тип или blend дают предупреждение |
| Ячейки и linked cels | Поддерживаются | Позиции, размеры, ссылки и opacity; отдельный z-index и precise bounds не поддерживаются и диагностируются |
| Длительности кадров, теги и их направления/повторы | Поддерживаются | Без обещания идентичного поведения всех игровых экспортёров |
| Палитры и покадровая смена цветов | Поддерживаются | Имена цветов не сохраняются; при импорте выдаётся предупреждение |
| Встроенные тайлсеты и tilemap-ячейки | Частично | Изображения и стандартные ссылки/отражения/повороты; дополнительные flags и нестандартные bitmasks диагностируются |
| Slices, center и pivot | Поддерживаются | Проверяются round-trip-тестами |
| Текст и цвет user data | Частично | Поддерживаются у слоёв, тегов, slices и тайлсетов; данные документа и cels диагностируются как пропущенные |
| Пользовательские свойства | Частично | Сохраняется специальное boolean-свойство `pixprite.clip`; остальные свойства дают предупреждение |
| Соотношение сторон пикселя | Поддерживается | Импорт и экспорт полей pixel width/height; нулевое значение любой оси означает `1:1`. Эквивалентные соотношения сокращаются |
| Цветовые профили | Частично | Обычный sRGB интерпретируется как sRGB; chunk профиля не сохраняется. ICC и нестандартная gamma не применяются и дают предупреждение |
| Внешние файлы и тайлсеты | Не поддерживаются | Ссылки не разрешаются; возможны пустые тайлы без встроенных пикселей. Выдаётся предупреждение |
| Дополнительные метаданные слоёв и UUID | Не поддерживаются | Выдаётся предупреждение; reference/movement-флаги не воспроизводятся |
| Неизвестные chunks и типы данных | Не поддерживаются | Неизвестные chunks пропускаются в проверенных границах и диагностируются; повреждённая структура отклоняется |
| Эффекты и трансформации экземпляров Pixprite | Запекаются | Экспорт сохраняет растровый результат; редактируемая модель остаётся в `.pixprite` |
| Референсы и направляющие Pixprite | Не экспортируются | Перечисляются в предупреждении перед сохранением копии |

## Предупреждения и защита исходника

При обнаружении неподдерживаемых данных редактор показывает предупреждение. Рабочий документ содержит только импортированную часть. Пропущенные chunks, ICC и внешние ресурсы не хранятся скрыто и не восстанавливаются из рабочей копии: исходный файл нужно сохранить отдельно.

Диагностика хранится в необязательном поле `asepriteWarnings` документа `.pixprite`, проходит валидацию и переживает автосохранение, Worker-подготовку и повторное открытие. Это список потерь, а не контейнер исходных данных.

Перед выгрузкой `.aseprite` из редактора или библиотеки показывается список обнаруженных потерь. Для импорта с предупреждениями предлагается имя `*-copy.aseprite`. Нативный диалог и MCP не заменяют существующие файлы при таком экспорте, даже если MCP передал `overwrite:true`; нужен новый путь. Запись нового файла атомарна и не затирает существующий путь при гонке.

В браузере успешный экспорт означает передачу загрузки браузеру; редактор не может проверить последующую запись на диск или управлять системным диалогом браузера. MCP возвращает `importWarnings` в inspect/open и `warnings` при сохранении копии.

## Проверки

Локальные `AsepriteWarnings.test.ts` используют небольшие бинарные файлы, созданные независимо от encoder Pixprite: неизвестные chunks, неквадратные пиксели, ICC, внешние ссылки и пользовательские свойства. Для pixel ratio проверяется сохранение метаданных без предупреждения о потере; для неподдерживаемых данных — диагностика, границы chunks, сохранение предупреждений через `.pixprite` и отказ при повреждённой диагностике. `PixelRatio.test.ts` проверяет заголовки `.aseprite`, round-trip и прежние нулевые значения. Браузерные сценарии проверяют отображение и ввод для `2:1`, `1:2`, `4:5`, `8:7`; native E2E — запись соотношения в реальный файл и неизменность исходника при попытке перезаписи импорта с потерями.

`bun run test:aseprite` скачивает три оригинальных файла из [официального набора тестов Aseprite](https://github.com/aseprite/aseprite/tree/3669f4774d181d77deb3e6db95fe6df8ca347410/tests/sprites). Ревизия закреплена: `3669f4774d181d77deb3e6db95fe6df8ca347410`. Файлы не включены в репозиторий Pixprite; проверке требуется сеть.

Проверяются импорт и повторное сохранение поддерживаемых данных:

- `tags3.aseprite`: RGB, размеры, 12 кадров, три тега с разным направлением, связанные и пустые ячейки, пиксели;
- `groups2.aseprite`: indexed, порядок и вложенность групп, видимость, корректная обработка старых групп без валидного поля opacity;
- `2x2tilemap2x2tile.aseprite`: размеры, пять тайлов, ссылки tilemap.

Это независимые входные файлы, созданные оригинальным Aseprite, а не собственным encoder Pixprite. Сравнивается поддерживаемая часть документа; диагностика пропущенных метаданных относится к входному файлу и не записывается в экспортируемый `.aseprite`. Обычный `bun test` пропускает сетевой сценарий; команда `test:aseprite` запускает его явно.

Обратное открытие экспорта Pixprite в оригинальном исполняемом файле Aseprite пока не автоматизировано. Три внешних fixtures и локальные синтетические файлы не доказывают полную поддержку формата. Полная реализация ICC, внешних тайлсетов и расширенных пользовательских свойств остаётся в [плане](roadmap.md).
