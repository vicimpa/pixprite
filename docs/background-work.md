# Фоновая обработка документов

Autosave, сохранение проекта, recovery snapshots, импорт `.pixprite` и подготовка экспорта используют `BackgroundTask.runTask` и `compute.worker.ts`. Синхронные `Sprite.toJSON`, `load` и `toDocument` сохранены для клиентов API и небольших синхронных операций.

`Sprite.captureDocument()` фиксирует метаданные, связи cels, ID общих images и сырые `Uint32Array` вместе. На основном потоке остаются обход модели, сверка старых изменяемых bitmap, слияние floating selection и копирование буферов; base64 и JSON ещё не создаются. `postMessage` копирует входные данные без transfer list: редактируемые buffers не отсоединяются. Worker кодирует images/tile references/tilesets, декодирует и мигрирует v3/v4, проверяет полный документ, вычисляет UTF-8 размер и создаёт PNG thumbnail через OffscreenCanvas. Результаты с самостоятельными выходными buffers передаются обратно через transfer list.

Для сохранения `IncrementalDocument` хранит clean/dirty состояние ресурсов по identity immutable `Image`. Чистое изображение передаётся Worker уже закодированным; новые изображения копируются и кодируются один раз. `imageOf` по-прежнему сверяет legacy mutable cels и приватные rendered bitmap; прямая запись в старый buffer создаёт новый dirty ресурс. Mutable tile references и tilesets сравниваются с сохранённым снимком buffers. Linked aliases и независимые transformed instances продолжают ссылаться на общий source image. Кеш привязан к живому документу через WeakMap; глобального кеша больших base64 payload нет.

`splitStorageDocument` и `hydrateStorageDocument` вычисляют SHA-256 и проверяют content-addressed ресурсы в Worker. Ключ включает вид/размеры buffer и его содержимое, а не пользовательский image ID. Поэтому независимые импорты с одинаковыми ID не подменяют пиксели друг друга, а подмена валидным base64 под старым ключом обнаруживается при чтении. Внутренние manifests не меняют публичный v5 `.pixprite`: load/export собирают полный самодостаточный документ. Полная JSON-нормализация и валидация подготовленного файла пока остаются частью каждого сохранения в Worker; инкрементальность сокращает кодирование новых pixels и записи payload в IndexedDB, а не весь обход модели/валидацию.

State фиксирует version, editor, header и raw snapshot до ожидания Worker. Превью и метаданные проекта/snapshot строятся из этого же снимка. Успешный save обновляет только захваченную version: правки во время фоновой работы остаются pending и попадают в следующую запись. В snapshot попадает та же версия, что в соответствующую рабочую копию. Preview имеет отдельную зависимость от rendering: изменения title/info/tags/editor не создают новый PNG; готовый thumbnail используется для проекта и snapshots, а отдельная запись preview меняется только при изменении thumbnail.

Autosave объединяет повторные flush-запросы в один текущий проход и один запрос на последние изменения. Если во время `prepareDocument` версия изменилась, AbortSignal завершает старый Worker; cancellation не показывает ошибку и не меняет `storedVersion`. Повторный capture ждёт 300 ms без новых edits, поэтому длинный burst не запускает Worker на каждое движение. Закрытый документ также отменяет подготовку. Граница отмены — подготовка перед записью: уже начатый save/атомарная IDB transaction может завершиться для захваченной версии, а более новые edits остаются pending и сохраняются следующим проходом. Явные saves сериализуются отдельно по документу, каждый фиксирует version/meta/editor в начале своей подготовки; они не отменяются последующими edits. `savedVersion` меняется только после commit этой версии; закрытая во время подготовки вкладка не создаётся заново.

Подготовка PNG/GIF/APNG, image sequences, sprite sheets, icons, tilemaps, `.aseprite`/`.pixprite` и ZIP выполняется в Worker. Он использует те же renderer/FX/transform и sheet primitives, что редактор. Сжатие APNG/Aseprite через CompressionStream, PNG encoding через OffscreenCanvas и GIF encoding также находятся там. GIF сохраняет progress overlay и отмену через AbortSignal. Для WebM Worker готовит кадры; DOM canvas, MediaRecorder и воспроизведение в реальном времени остаются на основном потоке. Предпросмотр sprite sheet в диалоге остаётся синхронным UI preview.

IndexedDB v8 сохраняет `revisions` из v7 и добавляет `resources`/`previews`, не переписывая старые документы. Новая и предыдущая версии проверяются до write transaction. Payload и revision token предыдущей версии читаются одним readonly snapshot; внутри atomic write проверяется тот же token. Если другая вкладка успела записать/удалить документ, проверка повторяется для новой предыдущей версии. Token, document/meta/editor и last-good изменяются одной транзакцией; abort откатывает всё. Удаление сохраняет tombstone: поздние save, session editor-only update и snapshot отклоняются, а закрытая вкладка пропускается после фоновой подготовки. Во время write transaction Worker не ожидается. Все штатные writers используют этот протокол; ручная запись в IndexedDB вне приложения не участвует в token coordination.

Если Worker отсутствует или его создание запрещено браузером (`SecurityError`/`NotSupportedError`), применяется тот же алгоритм на основном потоке. В этом режиме CPU-intensive document операции могут задерживать ввод; fallback не гарантирует отзывчивость больших документов. Отмена проверяется до работы и перед публикацией результата, а в поддерживающих шаги циклах — между элементами. Ошибки загрузки/исполнения уже созданного Worker и ошибки передачи результата возвращаются как `BackgroundWorkerError`, не маскируются fallback или «повреждённой предыдущей версией». Экспорт требует доступного OffscreenCanvas 2D, как и основной renderer.

Проверки:

- `bun test src/core/BackgroundDocument.test.ts src/core/SaveReliability.test.ts` — async/sync equivalence, миграции, shared resources и aliases, unknown extension data, malformed payloads, cancel, copy без detach, fallback, runtime failures, atomic rollback и конкурентный revision retry.
- `PIXPRITE_E2E_PREBUILT=1 bun run test:e2e --grep 'large autosave'` — production Chromium, настоящий Worker получает сырые pixels документа 2048×2048. Тест удерживает доставку настоящего результата Worker, вводит команды/рисует, затем проверяет отмену устаревшего autosave, последующие edits, dirty flags явного save, согласованность project metadata/data и reload. Это проверка маршрута и конкурентного ввода, не performance benchmark или численная гарантия latency.

- `bun test src/core/IncrementalStorage.test.ts` — фактические `IDBObjectStore.put` для metadata/pixels/preview; source identity и legacy writes; same-ID и different-dimension content keys; atomic resource rollback; GC всех владельцев; lazy inline migration; изоляция missing/swapped resources и Worker failure при hydrate.
- `PIXPRITE_E2E_PREBUILT=1 bun run test:e2e --grep 'incremental autosave|large autosave'` — настоящий Worker, cancellation устаревшей подготовки; восемь быстрых edits дают два prepare (отменённый и последний) и один session document write; metadata не кодирует images/не пишет resources/preview, один новый штрих пишет один новый image; final pixels и reload сверяются независимо по сохранённым refs.
