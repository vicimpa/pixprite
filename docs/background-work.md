# Фоновая обработка документов

Autosave, сохранение проекта, recovery snapshots, импорт `.pixprite` и подготовка экспорта используют `BackgroundTask.runTask` и `compute.worker.ts`. Синхронные `Sprite.toJSON`, `load` и `toDocument` сохранены для клиентов API и небольших синхронных операций.

`Sprite.captureDocument()` фиксирует метаданные, связи cels, ID общих images и сырые `Uint32Array` вместе. На основном потоке остаются обход модели, сверка старых изменяемых bitmap, слияние floating selection и копирование буферов; base64 и JSON ещё не создаются. `postMessage` копирует входные данные без transfer list: редактируемые buffers не отсоединяются. Worker кодирует images/tile references/tilesets, декодирует и мигрирует v3/v4, проверяет полный документ, вычисляет UTF-8 размер и создаёт PNG thumbnail через OffscreenCanvas. Результаты с самостоятельными выходными buffers передаются обратно через transfer list.

State фиксирует version, editor, header и raw snapshot до ожидания Worker. Превью и метаданные проекта/snapshot строятся из этого же снимка. Успешный save обновляет только захваченную version: правки во время фоновой работы остаются pending и попадают в следующую запись. В snapshot попадает та же версия, что в соответствующую рабочую копию.

Подготовка PNG/GIF/APNG, image sequences, sprite sheets, icons, tilemaps, `.aseprite`/`.pixprite` и ZIP выполняется в Worker. Он использует те же renderer/FX/transform и sheet primitives, что редактор. Сжатие APNG/Aseprite через CompressionStream, PNG encoding через OffscreenCanvas и GIF encoding также находятся там. GIF сохраняет progress overlay и отмену через AbortSignal. Для WebM Worker готовит кадры; DOM canvas, MediaRecorder и воспроизведение в реальном времени остаются на основном потоке. Предпросмотр sprite sheet в диалоге остаётся синхронным UI preview.

IndexedDB v7 добавляет отдельное хранилище `revisions`, не переписывая старые документы. Новая и предыдущая версии проверяются до write transaction. Payload и revision token предыдущей версии читаются одним readonly snapshot; внутри atomic write проверяется тот же token. Если другая вкладка успела записать/удалить документ, проверка повторяется для новой предыдущей версии. Token, document/meta/editor и last-good изменяются одной транзакцией; abort откатывает всё. Удаление сохраняет tombstone: поздние save, session editor-only update и snapshot отклоняются, а закрытая вкладка пропускается после фоновой подготовки. Во время write transaction Worker не ожидается. Все штатные writers используют этот протокол; ручная запись в IndexedDB вне приложения не участвует в token coordination.

Если Worker отсутствует или его создание запрещено браузером (`SecurityError`/`NotSupportedError`), применяется тот же алгоритм на основном потоке. В этом режиме CPU-intensive document операции могут задерживать ввод; fallback не гарантирует отзывчивость больших документов. Отмена проверяется до работы и перед публикацией результата, а в поддерживающих шаги циклах — между элементами. Ошибки загрузки/исполнения уже созданного Worker и ошибки передачи результата возвращаются как `BackgroundWorkerError`, не маскируются fallback или «повреждённой предыдущей версией». Экспорт требует доступного OffscreenCanvas 2D, как и основной renderer.

Проверки:

- `bun test src/core/BackgroundDocument.test.ts src/core/SaveReliability.test.ts` — async/sync equivalence, миграции, shared resources и aliases, unknown extension data, malformed payloads, cancel, copy без detach, fallback, runtime failures, atomic rollback и конкурентный revision retry.
- `PIXPRITE_E2E_PREBUILT=1 bun run test:e2e --grep 'large autosave'` — production Chromium, настоящий Worker получает сырые pixels документа 2048×2048. Тест удерживает доставку настоящего результата Worker, вводит команды/рисует, затем проверяет захваченный снимок, последующие edits, dirty flags, согласованность project metadata/data и reload. Это проверка маршрута и конкурентного ввода, не performance benchmark или численная гарантия latency.
