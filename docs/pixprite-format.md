# Формат `.pixprite`

`.pixprite` — JSON-документ с базовым объектом:

```json
{
  "format": "pixprite",
  "version": 6,
  "width": 32,
  "height": 32,
  "frames": [{ "duration": 100 }],
  "images": [{ "id": "red", "w": 1, "h": 1, "d": "/wAA/w==" }],
  "layers": [{ "name": "Layer 1", "cels": [{ "x": 0, "y": 0, "image": { "kind": "image", "id": "red" } }] }]
}
```

Текущая версия записи — **6**. Поддерживаемые версии чтения перечислены в `SUPPORTED_PIXPRITE_VERSIONS` в `src/core/SpriteValidation.ts` (также экспортируется из `Sprite.ts`): **3, 4, 5 и 6**.

## Основные данные

Документ хранит:

- размеры холста, имя и информацию о проекте;
- кадры и их длительности в миллисекундах;
- слои в порядке bottom-to-top, включая группы и уровни вложенности `depth`;
- ячейки каждого слоя и значения `celOpacity`;
- теги, slices, guides и loop-диапазон;
- RGB, grayscale или indexed color mode и покадровые палитры;
- тайлсеты и tilemap-ячейки;
- extension-метаданные документа, кадров, слоёв, ячеек, тегов и slices.

Пиксели упакованы как `0xAABBGGRR` и записываются в base64 из little-endian `Uint32Array`. В версии 5 таблица `images` содержит общие immutable-ресурсы `{id, w, h, d}`. Ячейка ссылается на ресурс через `image: {kind: "image", id}` и хранит свои `x`, `y`, а также необязательные `flipX`, `flipY`, `rotation` (0, 90, 180, 270 градусов по часовой стрелке), `opacity` (0..1). Отражение выполняется до поворота; позиция задаёт верхний левый угол результата. Значения по умолчанию: без отражений и поворота, opacity=1. Координаты могут выходить за холст: пиксели за его пределами сохраняются.

Пустая ячейка записывается как `null`. Если один объект ячейки используется в нескольких кадрах, повторные ячейки записываются как `{ "link": <индекс первого кадра> }`. Ссылка должна указывать на существующую более раннюю непустую ячейку того же слоя. Две независимые ячейки могут ссылаться на один Image и иметь разные трансформации; это не делает их связанными ячейками таймлайна.

Tilemap-ячейка дополнительно содержит `tc`, `tr` и `t` — количество столбцов, строк и base64-массив `Uint32` ссылок на тайлы. Flip flags хранятся в старших битах ссылки.

## Версия 3 → 4

Версия 3 хранила полноразмерный pixel buffer ячейки непосредственно в виде base64-строки. Версия 4 заменила его объектом с позицией и размерами, чтобы сохранять ячейки за пределами холста и обрезанные изображения.

Миграция `migratePixpriteV3` преобразует каждую строковую ячейку в:

```json
{ "x": 0, "y": 0, "w": 32, "h": 32, "d": "<base64>" }
```

Здесь `w` и `h` — размеры холста исходного документа. `null` и уже объектные ячейки не изменяются. После миграции документ проходит ту же валидацию, что и версия 4, затем выполняются миграции 4 → 5 → 6. Повторное сохранение всегда использует текущую версию 6.

## Версия 4 → 5

Версия 4 хранила `{x, y, w, h, d}` непосредственно в каждой несвязанной ячейке. `migratePixpriteV4` переносит `w`, `h`, `d` в таблицу Image и заменяет их ссылкой `image`. Миграция присваивает воспроизводимые ID `migrated-image-1`, `migrated-image-2`, …; linked refs, позиции, tile refs и `ext` сохраняются. Каждая стадия валидируется перед декодированием. Недопустимые старые буферы по-прежнему отклоняются; миграция не исправляет повреждение молча.

Слои могут содержать упорядоченный массив `effects`. Поддерживаемые процессоры — `{id, type: "opacity", enabled, amount}` с amount=0..1 и `{id, type: "outline", enabled, color, thickness, position, join}`. `color` — целое 0..4294967295 в формате 0xAABBGGRR; `thickness` — целое 1..128; `position` — inside/center/outside; `join` — round/miter/bevel. Интерфейс Layer FX позволяет добавлять, отключать, переставлять и запекать стек. Процессоры применяются последовательно; соседние включённые opacity объединяют множители до одного округления, сохраняя прежнюю семантику. Точная геометрия — [Outline](outline.md). Стек остаётся редактируемым при сохранении `.pixprite`. Неизвестные виды эффектов отклоняются, а не пропускаются при экспорте.

Live rendering и экспорт используют `bakeCel`: он запекает instance transforms/opacity и эффекты в новые пиксели, не изменяя Image. PNG, GIF, APNG и видео получают результат рендера; `.aseprite` получает ячейки из того же pipeline. Tilemap-слой с трансформированной ячейкой или эффектами растеризуется целиком при экспорте в Aseprite: исходные tile refs не могут заменять уже запечённые пиксели. `.pixprite` сохраняет исходные tile refs и трансформацию. Если instance/FX opacity создаёт alpha, которой нет в индексированной палитре, или включён Outline с произвольным цветом, Aseprite-экспорт переводится в RGB для сохранения запечённого изображения; режим самого `.pixprite` остаётся indexed. При первом рисовании по трансформированной tilemap-ячейке запекается только её размещение в собственные tile refs; остальные экземпляры сохраняют исходник.

## Версия 5 → 6

Версия 5 применяла `layer.effects` ко всем кадрам. Версия 6 добавляет `layer.bakedEffects`: массив длиной в число кадров, каждый элемент — массив уникальных effect ID, уже запечённых в этом кадре. Эти ID исключаются из живого стека только для соответствующего кадра. Отсутствующее поле или пустой массив кадра оставляет весь стек живым. Порядок `effects` сохраняется, новые effect ID действуют и на ранее запечённые кадры. Подробности операций и ограничений — [Layer FX](layer-fx.md).

`migratePixpriteV5` явно повышает версию до 6, сохраняя Image IDs/буферы, instances, links, metadata и эффекты без изменения; residual scope не добавляется. Поэтому прежние v5 FX продолжают действовать на все кадры, и миграция не меняет их изображение. Цепочка чтения — 3 → 4 → 5 → 6, каждая стадия валидируется. Запись и публичный Worker capture всегда используют v6, а storage manifest по-прежнему имеет внутреннюю версию `pixprite-resources-v1`.

Повышение версии обязательно: прежний v5 renderer не знает residual scope и повторно применил бы FX к уже запечённым пикселям. Версия 6 обеспечивает отказ такого reader через существующий `Newer pixprite version` guard, в том числе при rollback на прежнюю версию приложения. Нельзя объявлять документ с `bakedEffects` как v3/v4/v5: текущий loader отклоняет это до декодирования пикселей. Это изменение семантики формата, а не просто необязательное поле JSON.

## История формата

| Версия | Изменение |
| --- | --- |
| 3 | Полноразмерные inline cels |
| 4 | Позиции, размеры и off-canvas cels |
| 5 | Общие Image resources, CelInstance transforms и глобальный Layer FX stack |
| 6 | Покадровый residual Layer FX scope для частичного запекания; явная миграция v5 и безопасный отказ прежних readers |

Для каждой будущей старой версии должна быть отдельная миграция до следующей версии и отдельный round-trip-тест. Миграции выполняются до декодирования и выделения больших pixel buffers.

## Более новые и неизвестные версии

Файл с версией выше текущей отклоняется с сообщением `Newer pixprite version` и не открывается как редактируемый документ. Это предотвращает молчаливую потерю неизвестных полей и перезапись файла более новой версии в старом формате.

Неизвестные старые версии также отклоняются; молчаливая интерпретация их данных как одной из известных версий не допускается.

## Extension-метаданные

Ключи верхнего уровня `ext` — идентификаторы расширений. Значения должны быть JSON-совместимыми: `null`, boolean, finite number, string, array или object. Functions, symbols, bigint, `NaN`, `Infinity` и циклические структуры отклоняются.

Неизвестные extension-данные сохраняются при загрузке и повторном сохранении, даже если соответствующее расширение не установлено. Цвета в палитрах, тегах, slices и user data должны иметь hex-формат `#rgb`, `#rgba`, `#rrggbb` или `#rrggbbaa`.

## Проверки безопасности

До декодирования pixel data проверяются:

- целые положительные размеры документа, ячеек и тайлсетов;
- ограничение каждого измерения значением 4096 и общего pixel budget;
- наличие кадров и слоёв и согласованность длин `cels` с количеством кадров;
- длины pixel buffers и tile reference buffers;
- уникальные Image ID, существование AssetRef, размеры Image и диапазоны трансформаций/эффектов;
- корректность linked cel refs, layer tileset refs и tile indices;
- допустимые цвета и extension-метаданные.

Усечённые бинарные данные и неверные размеры буферов отклоняются с ошибкой. Редактор показывает имя файла и причину ошибки, не открывая повреждённый документ.

Длина base64 проверяется до выделения pixel buffers. Все буферы и ссылки нового `.pixprite` декодируются и проверяются до замены текущей модели: ошибка импорта сохраняет прежний документ и его undo/redo. Бинарные Aseprite/APNG-данные распаковываются с ограничением, вычисленным из проверенных размеров; превышение отменяет чтение потока.

## Outline в v6

Outline добавляет новый строго валидируемый discriminant без изменения версии: прежний v6 reader отклоняет неизвестный `effect.type` до загрузки, поэтому не может молча перезаписать такой файл. Неизвестные типы и неправильные параметры отклоняются до декодирования Image. Версии 3–5 проходят прежние миграции.

Границы результата проверяются до выделения output buffers. Изменение исходной геометрии после Apply может временно приостановить слишком большой стек: настройки enabled и Image сохраняются без изменений, load допускает такое состояние, renderer выводит ограниченный fallback и предупреждение. После уменьшения геометрии FX возобновляются. PNG/GIF/video используют тот же fallback; Bake и Aseprite отказывают до записи результата. Подробности — [Outline](outline.md#bounds-and-performance).

Включённый Outline также переводит grayscale → RGB при Bake/Aseprite export, чтобы цвет контура не превращался в яркость. Стек только из opacity сохраняет grayscale. Режим исходного редактируемого документа при экспорте не меняется.


## Другие эффекты и Lock Alpha в v6

Стек также поддерживает `{id, type:"shadow", enabled, color, x, y, size}`, `{id, type:"glow", enabled, color, size, position}` и `{id, type:"overlay", enabled, color}`. `color` — unsigned RGBA 0…4294967295; X/Y тени — целые −1024…1024, размер тени — целый 0…128. Размер Glow — целый 1…128, положение — `inside|outside`. Все параметры и неизвестные discriminants проверяются до декодирования пикселей. Inner Outline — явный UI preset существующего `outline` с `position:"inside"`. Точная геометрия blur, falloff, alpha и bounds описана в [Layer FX](layer-fx.md#drop-shadow-glow-and-color-overlay).

Необязательное `layer.lockAlpha` — boolean с default false. Оно сохраняет исходную alpha при pixel editing, включая кисти/ластик, заливки/градиенты, фильтры и extension `putPixels`; структурные преобразования и запекание действуют независимо. UI — **Свойства слоя → Заблокировать альфу**; API — `LayerInfo.lockAlpha` / `sprite.layers.update`. Неверный тип поля отвергается атомарно. Это ограничение редактирования, которое не меняет изображение и формат ресурсов, поэтому версия остаётся 6; старый reader может не поддерживать ограничение. Новые FX безопасно отвергаются уже существующей проверкой unknown effect type.
