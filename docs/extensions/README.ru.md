# Расширения Pixprite

[English version](README.md)

Расширения добавляют в Pixprite команды, инструменты, фильтры, панели, импорт/экспорт, темы и языки.
Они работают в песочнице: код точки входа — в модульном **Web Worker**, панели и виджеты — в **изолированных iframe**
(`sandbox="allow-scripts"`, без same-origin). Каждый вызов API — асинхронное сообщение редактору, который
сверяет его с разрешениями из манифеста.

## Быстрый старт

```sh
cp -r extensions/template extensions/my-ext   # затем "id": "my-ext" в manifest.json
bun run ext:dev                               # раздаёт исходники на http://localhost:5174 и следит за ними
bun run dev                                   # редактор
```

В редакторе откройте **Расширения → Разработчик**, введите `http://localhost:5174` (все расширения, которые
собирает сервер) или `http://localhost:5174/my-ext/` (одно из них) и загрузите. Дальше, пока редактор открыт:

- **Живая перезагрузка.** Сохранили файл расширения (или `packages/api`) — редактор сразу перезагружает его
  вместе с открытыми панелями. Если проверки не прошли, редактор покажет почему.
- **Ошибки в вашем терминале.** Необработанные исключения, отклонённые промисы и `console.error` / `console.warn`
  из worker и панелей расширения печатает `ext:dev` — со стеком и указанием, откуда они пришли.

```ts
// extensions/my-ext/src/main.ts
import { defineExtension } from "@pixprite/api";

export default defineExtension(ctx => {
  ctx.commands.register('hello', async () => {
    const s = await ctx.sprite.get();
    await ctx.ui.notify(ctx.i18n.t('hello', { w: s.width, h: s.height }));
  });
});
```

## Структура и сборка

```
extensions/<id>/
  manifest.json
  src/main.ts          → main.js      ("entry": "main.js" в манифесте)
  src/panel.ts         → panel.js     (страница "panel.html")
  src/panel.html       необязательно; иначе генерируется пустая страница, подключающая panel.js
  locales/en.json      свои строки, обязателен, если манифест использует %key%
  locales/ru.json …
  assets/              копируется как есть
```

Сборки нет. Расширение хранится исходниками, и редактор компилирует их сам, когда устанавливает или
запускает его: у каждого `.ts` убираются типы (sucrase), импорты прослеживаются по пакету, а `@pixprite/api` —
собственная копия API редактора. Поэтому импортировать можно только файлы самого расширения (относительными
путями) и `@pixprite/api`: без npm-пакетов и без циклов.

| Скрипт | Что делает |
|---|---|
| `bun run ext:check` | проверяет манифесты, исходники, наборы ключей локалей, плейсхолдеры и ссылки `%key%` |
| `bun run ext:dev` | раздаёт исходники и каталог с CORS на порту 5174, перезагружает расширения в редакторе при изменениях, печатает их ошибки |

Можно передать id, чтобы ограничить запуск: `bun run ext:check game-rig`.

В dev-сервере самого редактора (`bun run dev`) встроенный каталог — это папка `extensions/`: магазин
показывает все расширения из неё, а установленное переустанавливается, когда меняются его файлы.
Production-сборка редактора не включает расширения: отдельный workflow публикует каталог и исходники в ветку `extensions`. Каталог (`registry.json`) строится по исходникам:
тексты на каждом языке, sha256 каждого файла (проверяется при установке), а у языковых пакетов
`completeness` — процент переведённых ключей ядра.

## Манифест

Полный пример с комментариями — в [английской версии](README.md#manifest-reference); поля те же.
Главное:

- `id` — `[a-z0-9]` с `.` / `-`, он же пространство имён `ext.<id>.*`; имя папки совпадает с `id`;
- `version` — semver, `apiVersion: 1`;
- `entry` — воркер (`main.js` запускает `src/main.ts`); без него расширение только с данными (темы, иконки, языки);
- `public` — `false` оставляет расширение в репозитории и не публикует его (шаблоны, незаконченное); по умолчанию `true`;
- команды, инструменты, фильтры, импорт и экспорт требуют `entry`; панели и виджеты — разрешения `ui:panel`;
- пути относительные, без `..`; коды языков — корректный BCP 47.

**FormSchema** — массив `{ key, type, label, min?, max?, step?, options?, default? }`, где `type` —
`slider | number | color | select | checkbox | text | layer | tag`. Редактор рисует форму своими контролами.

**Наборы иконок** — расширения без кода и разрешений. В манифесте укажите:

```json
{ "contributes": { "iconPacks": [{ "id": "duotone", "label": "%icons.label%", "icons": "icons.json" }] } }
```

Установите расширение и выберите набор в меню «Окно → Набор иконок» (выбор есть и в настройках). Предпросмотр обновляется сразу; выбор сохраняется отдельно от цветовой темы. Размеры кнопок не меняются. Контурные и пиксельные иконки встроены и доступны офлайн без расширений; по умолчанию выбраны контурные. Недостающие иконки берутся из контурного набора; при отключении или удалении расширения включается тот же запасной вариант. Повторное включение выбранного расширения восстанавливает его иконки.

`icons.json` — объект с именами из [встроенного набора](../../src/ui/Icon/icons.ts), например `pencil`, `eraser`, `play`, `gear`. Набор может заменять только часть иконок. Значение — либо `{ "pixels": "#.\n##" }`, либо `{ "size": 24, "paths": [{ "d": "M4 20 20 4" }] }`. У векторного пути доступны только `d`, `fill`, `stroke`, `strokeWidth`; цвета — `foreground`, `accent`, `fill` (заливка иконок из темы), `none`. По умолчанию нет заливки, контур цвета текста толщиной 1.75, скруглённые концы и соединения. В пиксельной сетке `#` — текст, `o` — заливка, `+` — акцент, `.` — прозрачность.

Пиксельные сетки прямоугольные, до 64×64; размер векторного холста — 1–128, до 64 путей на иконку. Лимит файла — 256 KiB, до 256 иконок. Длина путей и координаты ограничены; SVG/HTML, обработчики событий и внешние URL не принимаются. Файлы проверяются обычными хешами пакета. В редактор встроены полные [пиксельный](../../src/ui/Icon/icons.ts) и [контурный](../../src/ui/Icon/outline.json) наборы, по 63 иконки. [Пример расширения Duotone](../../extensions/icons-duotone) содержит 16 оригинальных двухцветных иконок, остальные подставляются из контурного набора. `bun run ext:check` проверяет графику расширения, unit-тесты — полноту встроенных наборов. Сохранённый выбор `builtin` и прежние ID пиксельного/контурного расширений продолжают работать.

**Темы** задают css-переменные редактора. Тема перечисляет только то, что меняет, остальное берётся из темы по умолчанию (в `src/themes/dusk.json` есть все переменные со значениями).

| Группа | Переменные |
|---|---|
| Текст и поверхности | `--fg --fg-dim --bg --bg2 --b1 --b2 --field --menu --workspace` |
| Кнопки и рельеф | `--face --face-hot --face-down --hilite --shade --icon-fill` |
| Акценты | `--accent --accent-fg --sel --sel-fg --danger --tooltip --tooltip-fg` |
| Тени | `--shadow` (всплывающие окна, диалоги), `--shadow-inset` (нажатые кнопки), `--backdrop` (затемнение под диалогом) |
| Таймлайн | `--onion` (диапазон onion skin), `--row-hover` (строка под курсором и текущая), `--row-sel` (выделенные ячейки) |
| Холст | `--ruler --ruler-fg` (линейки), `--guides`, `--layer-edges` |

Темой намеренно не меняются: шахматка прозрачности и цвета сетки (это настройки пользователя, доступны только для чтения как `--checker-a` / `--checker-b`), градиенты в пикерах цвета и чёрно-белые обводки поверх пикселей (выделение, хэндлы): они должны быть видны на любом рисунке.

## Разрешения

| Разрешение | Даёт |
|---|---|
| `sprite:read` | `sprite.get/getPixels/render`, выделение, события спрайта |
| `sprite:write` | запись пикселей, изменения слоёв / кадров / тегов / срезов, транзакции |
| `tags:lock` | `ctx.locks`: структурные блокировки, которые соблюдает ядро |
| `ui:panel` | панели и виджеты |
| `storage` | `ctx.storage`, хранилище ключ/значение в IndexedDB для расширения |
| `network:<host>` | `ctx.net.fetch` только к этому хосту (`network:*` — к любому, лучше не надо) |
| `clipboard` | зарезервировано |

Перед установкой магазин показывает запрошенные разрешения. Вызов без разрешения отклоняется с
`ExtensionError` (`code: 'permission'`).

## Обзор API

`ctx` (`ExtensionContext` в `packages/api/src/context.ts`) одинаков в воркере (`defineExtension`) и в панелях
(`await connect()`). Всё возвращает промисы.

| Область | Главное |
|---|---|
| `sprite` | снимок `get()`, `getPixels`, `putPixels`, `render(frame, {scale, format})`, `transaction(label, fn)` — один шаг отмены, CRUD `layers/frames/tags/slices`, `palette.set(colors, {keepPixels})`, `selection.get/set` |
| `documents` | `list`, `active`, `open`, `create`, `on('change')`; `DocumentInfo.project` — постоянный ключ проекта для ваших данных о нём |
| `events` | `on('sprite:change'│'selection'│'frame'│'tool'│'tags'│'playback'│'history', cb)` |
| `commands` | `register`, `run(id, ...args)` (встроенные с аргументами, публичные команды других расширений), `list()` с `params`; см. ниже |
| `tools` | `register(id, {onDown, onMove, onUp, onCancel})`, `overlay(pixels)` — превью штриха |
| `filters`, `io` | фильтры `(pixels, options) => pixels`, импортёры и экспортёры |
| `ui` | `notify`, `confirm`, `prompt`, `pickColor`, `pickFile`, `progress`, `showForm` |
| `view`, `state`, `playback` | масштаб/сдвиг и пересчёт координат, `reveal({layer, frame, rect, highlight})` — показать изменённое место; fg/bg/tool/brushSize; play/stop/seek |
| `meta` | данные спрайта/слоя/кадра/тега/среза/ячейки под вашим id, сохраняются в файле проекта |
| `storage` | `get/set/delete/keys` |
| `locks` | `set({tags: {delete: true}, constraints: {frameMultiple: 4}})`; ядро отклоняет ломающие правки и показывает это в интерфейсе. Документ помнит владельца; без расширения предлагается снять блокировку |
| `validators` | `register(id, snapshot => Problem[])`, вывод в панели «Проблемы» |
| `i18n` | `t`, `core`, `lang`, `dir`, `on('change')`, `number/date/list` |
| `extensions` | `get(id)` → `{ api }` того, что вернул `activate` другого расширения |
| `net` | `fetch(url, init)`, ограниченный `network:<host>` |

Пиксели — `{rect, format, data: Uint8ClampedArray}`, 4 байта на пиксель, альфа не домножена. Буферы
передаются (transfer), а не копируются: не используйте буфер после отправки.

## Команды

Всё, что есть в меню редактора, — команды, и `ctx.commands.run(id)` выполняет их так же, как пользователь.
Команды, которые спрашивают настройки в диалоге (эффекты, размер холста и спрайта, цветовой режим, свойства
слоя, кадра и ячейки, расширение/сужение/обводка выделения…), принимают ещё и объект аргументов: тогда
применяются сразу, без диалога. `ctx.commands.list()` отдаёт для них `params` (`FormSchema`: ключи, диапазоны,
значения по умолчанию); пропущенные аргументы берутся по умолчанию, неверные — ошибка.

```ts
await ctx.commands.run('image.canvasSize', { width: 64, height: 64, anchorY: 1 });
await ctx.commands.run('fx.outline', { color: '#1b1a24', scope: 'layer' });
```

**Между расширениями.** Команда с `"public": true` — часть API вашего расширения: другие вызывают её как
`ctx.commands.run('<ваш id>:<id команды>', ...args)` и получают то, что вернул обработчик. Опишите аргументы
в `params`, чтобы их показывал `list()`. Команды без `public` могут запускать только пользователь и само
расширение. Для API побогаче (объекты, несколько функций) верните его из `activate` — другие получат его через
`ctx.extensions.get(id)`.

## Локализация

- Свои строки — в `locales/<lang>.json`, ключи **без** префикса `ext.<id>.`; эталон — `en.json`.
- В манифесте пишите `"%key%"` — редактор подставит строку, не запуская ваш код.
- В коде `ctx.i18n.t('key', { name })` подставляет `{name}`; `ctx.i18n.core('common.ok')` — строки ядра.
- Множественное число: задайте `key.one`, `key.few`, `key.many`, `key.other` и передайте `count`.
  Форма выбирается через `Intl.PluralRules`; в английском обязателен только `key.other`.
- Цепочка: выбранный язык → базовый (`pt-BR` → `pt`) → `en` → сам ключ.
- `ctx.i18n.dir` равен `rtl` для языков справа налево; используйте логические css-свойства.
- **Языковые пакеты** — расширения без кода с `contributes.languages`: плоский `dict` ключей ядра (можно частично,
  недостающее берётся из английского) и переводы для других расширений. Пример — `extensions/lang-uk`.

## Публикация

1. Сделайте форк и добавьте `extensions/<id>/`.
2. Должны проходить `bun run ext:check` и `bun run typecheck`.
3. Нужен хотя бы `locales/en.json`; другие языки приветствуются.
4. Запрашивайте только нужные разрешения; хосты `network:` поясните в PR.
5. Поднимайте `version`, когда меняются файлы расширения (проверка в PR иначе не пропустит): установленные
   копии узнают об обновлении только по большей версии.
6. Откройте pull request. После слияния расширение появится в магазине редактора.

В сборке самого редактора расширений нет. Их публикует `.github/workflows/extensions.yml` в orphan-ветку
`extensions`: исходники всех расширений, кроме `"public": false`, и `registry.json`. Магазин читает её через
jsDelivr (`https://cdn.jsdelivr.net/gh/vicimpa/pixprite@extensions/registry.json`); путь каждого пакета в нём
закреплён на коммите его исходников, поэтому файлы кешируются навсегда, а манифест никогда не встретится со
старыми исходниками. Другие каталоги добавляются в «Настройки → Каталоги расширений».

## Примеры

| Папка | Что показывает |
|---|---|
| `extensions/template` | команда, панель, локали с плюрализацией, экспорт api |
| `extensions/theme-neon` | тема без кода |
| `extensions/icons-duotone` | двухцветные иконки без кода, с подстановкой недостающих из встроенного контурного набора |
| `extensions/lang-uk` | языковой пакет без кода (частичный украинский) |
| `extensions/game-rig` | наборы тегов в meta, блокировки, валидатор, экспорт (zip с sheet.png + rig.json), живой игровой предпросмотр |
| `extensions/ai-assistant` | чат с OpenAI-совместимым API (по умолчанию DeepSeek), вызовы функций через ctx, каждая правка ИИ — один шаг отмены |
