# Bundle и загрузка

По решению от 2026-10-31 весь встроенный редактор собирается в один JavaScript-бандл. Home, рабочая область, диалоги, магазин расширений и main-thread fallback кодеков доступны после запуска без дополнительных UI-загрузок. `inlineDynamicImports` включён отдельно для main и Worker: вычислительный Worker имеет собственный самостоятельный JS-файл, включая его кодеки. CSS, шрифты, изображения и JSON-словари остаются отдельными ресурсами.

Входной HTML содержит анимированную заставку с логотипом и индикатором без выдуманного процента. Она видна до скачивания JS и снимается после восстановления сессии, загрузки языка/темы и первого React commit. `prefers-reduced-motion` отключает движение. При ошибке начального скрипта остаётся кнопка Retry, перезагружающая страницу. Встроенные UI-компоненты и диалоги импортируются статически; промежуточные Suspense/loading-окна удалены.

Форматные операции всё ещё запускаются через `runTask`: сериализация, сжатие, подготовка экспорта и валидация выполняются вне UI-потока. Если Worker недоступен, тот же код работает в основном бандле с прежними проверками отмены и изоляцией входных данных. Модульная структура исходников и `import()` для вычислений сохраняются, но в production новые JS-чанки из них не создаются.

## Расширения

Пакеты из `extensions/`, включая AI assistant и game-rig, остаются самостоятельными артефактами публичного Extension API. Их код не включается в редактор. Установленные расширения запускают собственные sandbox Workers и iframe как прежде; ограничение «один бандл» относится к встроенному коду приложения. Dev-каталог и отдельный production workflow расширений сохраняются.

## Проверки и размеры

```sh
bun run build
bun run bundle:check
bun run bundle:graph
PIXPRITE_E2E_PREBUILT=1 bun run test:e2e e2e/bundle.e2e.ts e2e/pwa.e2e.ts
```

Vite пишет `.vite/manifest.json`, `.vite/main-graph.json` и `.vite/worker-graph.json`. Gate требует ровно один browser entry, самостоятельные Worker entries без дополнительных JS imports/dynamic chunks, наличие встроенных UI/кодеков и отсутствие исходников устанавливаемых расширений в обоих графах. Отдельные benchmark entries могут разделять свой диагностический код и не входят в `dist/web`.

После объединения бандла initial составляет около 372 KB gzip, весь JavaScript вместе с Worker и SW — около 399 KB (gzip level 9; точные значения печатает `bundle:graph`). Initial budget изменён с 300 KiB на 380 KiB: теперь в первый файл входят все ранее отложенные UI и форматы. Общий budget оставлен 400 KiB. Возросшая стоимость первого файла — осознанный обмен на один запуск без последующих загрузок интерфейса; заставка покрывает первоначальное ожидание.

Browser regressions задерживают/обрывают основной скрипт, проверяют заставку и Retry, затем впервые открывают диалоги, переходят Home ↔ editor, импортируют GIF и экспортируют PNG offline с заблокированным SW и выключенным Worker. Они фиксируют отсутствие новых JS-запросов и loading-placeholder. Отдельный сценарий проверяет WebM-контейнер; native MCP E2E использует настоящий Worker.

## PWA и offline

Production SW precache-ит полный build: HTML, browser bundle, Worker, CSS, словари, шрифты и public-файлы. После установки и первого controlled открытия встроенные функции доступны offline. Версионирование release snapshots, integrity, отложенная активация и сохранность документов описаны в [service-worker.md](service-worker.md).

`public/manifest.webmanifest` уже объявляет `file_handlers` для `.pixprite`, `.aseprite`/`.ase`, PNG/GIF/WebP/JPEG и палитр GPL/PAL/HEX/ACT. В установленной настольной PWA Chromium эти ассоциации могут появляться в системном «Открыть с помощью»; выбор обработчика и разрешение контролируются браузером/ОС. Это требует установки с HTTPS или localhost и не является универсальной возможностью всех браузеров. См. [File Handling API Chrome](https://developer.chrome.com/docs/capabilities/web-apis/file-handling).

`launchQueue` регистрируется до окончания запуска. Полученные файлы ожидают восстановления сессии и переводов, затем открываются вкладками даже с домашнего экрана. Запуски обрабатываются последовательно; недоступный handle не мешает остальным файлам, ошибки не превращаются в unhandled rejection. Обычный импорт с Home по-прежнему сохраняет проекты в библиотеку; статические изображения, переданные вместе, импортируются как последовательность кадров. Тест `e2e/file-handling.e2e.ts` проверяет manifest и доставку файлов при старте/повторном запуске. Регистрацию ассоциаций в конкретной ОС нужно проверить вручную после установки PWA.

Настольные установщики с собственными файловыми ассоциациями и MCP описаны в [desktop-mcp.md](desktop-mcp.md).
