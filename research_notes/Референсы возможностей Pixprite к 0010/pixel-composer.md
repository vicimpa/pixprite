# Pixel Composer как продуктовый референс

## 1. Что представляет собой продукт и какие семейства возможностей подтверждены

### Takeaway

Pixel Composer полезен для Pixprite прежде всего как референс процедурного изготовления игровых ассетов и VFX: пользователь собирает рецепт из операций, управляет его параметрами и временем, затем получает изображения и анимации. Его каталог значительно шире 2D-фильтров, но заимствовать всё это сразу для 0.0.10 не требуется. Ниже описано поведение, а не предлагаемое устройство Pixprite.

### Cited Findings

Приложение не устанавливалось и не запускалось; подтверждение документацией/наличием исходников не является ручной приёмкой продукта. [Срез репозитория](https://github.com/Ttanasart-pt/Pixel-Composer/commit/d4d2468706530082d57733776835593e2c107497).

README называет продукт node-based VFX editor for pixel art. Авторская вводная документация описывает создание сложных анимированных визуальных эффектов процедурным способом. Это заявленное назначение, а не доказательство качества каждого отдельного генератора. ### Inferences

- Самая полезная модель для Pixprite: входные ресурсы и управляющие значения → несколько осмысленных операций → предпросмотр → воспроизводимый рецепт → обычный игровой растр/кадры. Эта ценность не требует копирования интерфейса, языка выражений, структуры файлов или вычислителя Pixel Composer.
- Пиксельный характер результата здесь задаётся не одним генератором: важны палитра, квантование/дизеринг, выбор интерполяции и целочисленное размещение. Для пользовательского WOW это существеннее общего количества нод.
- 3D, кости, аудио и физические симуляции показывают широту продукта, но в 0.0.10 Pixprite разумнее использовать их как дальний ориентир, а не условие первого процедурного сценария.

### Gaps

- `main` изучен, но отдельная stable-ветка не клонировалась и весь каталог не сопоставлен с каждой версией. Возможности из текущих исходников не объявляются все гарантированно доступными в stable 1.22.0.5.
- В старой ReadTheDocs-вводной мало актуальной навигации. В репозитории `docsdata/readme.md` новым адресом указан `docs.pixel-composer.com`; обращение к нему не завершилось, поэтому подробный анализ основан на закреплённых авторских файлах документации.
- Клон на файловой системе macOS сообщил о коллизиях регистра путей в сгенерированных `docs/nodes/Iteration` и `docs/nodes/iteration` и аналогичных разделах. Для чтения использованы исходные страницы `docsdata/content`, а не неоднозначные generated HTML.
- Отдельные node pages короткие/частично автогенерируемые. Наличие имени не доказывает качество результата. Код рендера и программы не исполнялись.
- Старый `Canvas` в документации помечен deprecated с заменой. По release notes в 1.22 есть обновлённое рисование, но этот аудит не утверждает равенство его ручного редактора набору слоёв/инструментов Pixprite.

## 2. Что сохраняется, как управляется анимация и как получается игровой ассет

### Takeaway

Сильная сторона Pixel Composer — повторное использование **самого рецепта и его управления**, а не только экспортированных пикселей. Анимация, варианты и экспорт являются продолжением того же графа; при этом случайность, циклы графа и бесшовность имеют разные, явно ограниченные механизмы.

### Cited Findings

- **Группы с контрактом:** несколько узлов группируются; Group Input и Group Output создают внешние входы и выходы. Пользователь может скрыть внутреннюю сложность за одним инструментом. [Group](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/__nodes/node_group.md), [Input](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/__nodes/node_group_input.md), [Output](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/__nodes/node_group_output.md).
- **Коллекции между проектами:** выделенный набор узлов сохраняется в коллекцию, имеет метаданные/папки и повторно используется в другом проекте; документация описывает обмен файлами и через Steam Workshop. Это самостоятельный сохраняемый пользовательский результат. [Collection panel](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/2_interfaces/collection_panel.html).
- **Сохранённые настройки и внешние параметры:** инспектор сохраняет preset значений узла, `_default` становится его значениями по умолчанию. Проект имеет общие dimension/palette и глобальные переменные, доступные из выражений и переопределяемые CLI. [Inspector](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/2_interfaces/inspector_panel.html), [CLI](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/99_misc/command_line.html).
- **Пакеты вариантов:** Array Processor обрабатывает массив входов. Для нескольких массивов есть Loop, Hold, Expand и обратный Expand; Expand создаёт комбинации параметров. Это сценарий нескольких цветовых/форменных вариантов из одного рецепта, а не ручного дублирования графа. [Array processor](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/3_nodes/002_array_processor.html).
- **Ключевые кадры:** большинство входных свойств можно анимировать; изменение значения создаёт ключ текущего кадра. Есть Linear, Smooth и Hold, просмотр кривой и разделение осей вектора на отдельные дорожки. Нельзя автоматически анимировать любое техническое свойство: attributes отдельно описаны как неанимируемые. [Animation](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/4_animations/0_index.html), [Attributes в basics](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/3_nodes/000_index.html).
- **Драйверы поверх ключей:** Linear добавляет изменение по кадрам, Sine даёт периодическое изменение, Wiggle имеет seed/frequency/amplitude/octave и синхронизацию осей. [Drivers](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/4_animations/driver.html).
- **Управляемая случайность:** вход Seed есть у Simplex Noise и Particle; в Particle исходник явно устанавливает random seed при вычислении. Это подтверждает наличие управляющего параметра, но этот аудит не проверял побитную идентичность результата между платформами/версиями. [Noise seed](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/scripts/node_noise_simplex/node_noise_simplex.gml#L17), [Particle seed](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/scripts/node_particle/node_particle.gml#L7).
- **Повторение и бесшовность времени:** документация различает Hold, Loop, Pingpong и Wrap, который соединяет начало и конец. Ограниченный диапазон петли выбирается отдельно. Нельзя интерпретировать любой Loop как автоматически бесшовную визуальную анимацию. [Keyframe looping](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/4_animations/looping.html).
- **Специальная петля частиц:** Particle имеет Loop, для которого заранее рассчитывается вся симуляция до первого кадра; автор предупреждает о сильном влиянии на производительность. Это специальный VFX-механизм, а не свойство любого графа или входа времени. [Particle / Render Loop](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/__nodes/node_particle.md).
- **Обратная связь с задержкой:** обычные связи не разрешают цикл и связь входа/выхода одного узла. Feedback System выделен отдельно: результат передаётся входом на следующий кадр. Старый групповой Feedback deprecated в пользу inline-варианта. Поэтому «граф без произвольных циклов» и «есть feedback-эффекты» не противоречат друг другу. [Connection restrictions](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/3_nodes/000_index.html), [Feedback inline](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/__nodes/node_feedback_inline.md), [deprecated Feedback](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/__nodes/node_feedback.md).
- **Проверяемость и кеш:** граф показывает покадровую заполненность кеша; изменение свойств его обновляет, есть ручной Clear Cache. Cache node отдельно сохраняет закешированную анимацию в проекте между сессиями. Это важно различать с сохранением рецепта: кешированный результат — ещё один вид сохраняемых данных. [Cache behaviour](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/3_nodes/000_index.html), [Cache node](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/__nodes/node_cache.md).
- **Результат для движка:** Render Sprite Sheet превращает массив или анимацию в лист, имеет packing/spacing/padding, frame step и диапазон. Для анимации предварительно нужен проход от начала до конца. Image Sheet выполняет обратную операцию. Это мост между процедурным инструментом и обычным asset pipeline. [Render Sprite Sheet](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/__nodes/node_render_sprite_sheet.md), [Image Sheet](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/__nodes/node_image_sheet.md).
- **Экспорт:** изображение PNG/JPEG/WebP, последовательность изображений и GIF/APNG/MP4/WebM перечислены у Export node; есть индексированные PNG, диапазон, шаг кадров, частота/длительность и шаблоны имён с номером кадра/индексом массива. Для получения спрайтшита используются отдельная укладка и экспорт изображения. Не следует приписывать узлу Export все виды метаданных игровых движков без дополнительной проверки. [Export node](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/__nodes/node_export.md).
- **Headless как отдельный продуктовый путь:** подготовленный `.pxc` с Export node запускается с глобальными параметрами без GUI. Документация предупреждает, что вывод stdout требует отдельной оболочки; недоверенные shell-execute nodes по умолчанию отключены. Это подтверждённая автоматизация Pixel Composer, но не обязательство добавить CLI в первый процедурный этап Pixprite. [CLI](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/99_misc/command_line.html).

### Inferences

- Полезный ориентир сохранения: отдельно мыслить рецепт, пользовательские значения параметров, внешние ресурсы и экспортированные пиксели. Это продуктовые сущности; выбранный формат/модель хранения Pixprite остаётся открытым.
- Пространственная бесшовность текстуры и временная бесшовность анимации требуют разных критериев приёмки. Повторение картинки на Preview помогает найти пространственный шов; оно ничего не доказывает о стыке последнего и первого кадра.
- Для первой версии Pixprite достаточно предсказуемого ограниченного графа/рецепта и сквозного сохранения/применения. Для физики, feedback и произвольных временных зависимостей понадобится отдельная оценка, они не должны скрытно стать обязательной основой.

### Gaps

- Не проверена точная устойчивость seed по GPU/ОС/версиям приложения и одинаковость симуляции при случайном переходе по timeline.
- Не подтверждён универсальный автономный перенос любого сохранённого графа со всеми внешними файлами; наличие коллекций не доказывает упаковку всех зависимостей.
- Не проверено, какой набор анимационных свойств поддерживает smooth loop при сложных нелинейных/симуляционных зависимостях.
- Не проверены полнота экспорта метаданных спрайтшитов для конкретных движков и доступность всех кодеков на каждой ОС. Release notes 1.22 отдельно говорят, что FFmpeg больше не поставляется вместе с приложением и загружается отдельно; это ограничение опубликованного продукта, не рекомендация зависимости для Pixprite. [Release notes](https://makham.itch.io/pixel-composer/devlog/1680231/122-full-release-note).

## 3. Какие законченные сценарии стоит рассматривать для Pixprite 0.0.10

### Takeaway

Рекомендую **переиспользуемую параметризованную текстуру** как обязательную демонстрацию, а **короткую зацикленную воду** как соседний stretch. Для itch.io важно показать полезный результат, редактирование и повторное применение рецепта, а не пустой нодовый холст или счётчик операций. Все предложения в этом разделе — выводы для Pixprite, не обещание текущей реализации и не выбранная архитектура.

### Cited Findings

Основание предложений — подтверждённая в Pixel Composer комбинация tileable noise с seed, color mapping/dither, групп и коллекций, экспорта изображения и кадров. Вспомогательные референсы: [Simplex noise](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/__nodes/node_noise_simplex.md), [Colorize](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/__nodes/node_colorize.md), [Collection](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/2_interfaces/collection_panel.html), [Render Sprite Sheet](https://github.com/Ttanasart-pt/Pixel-Composer/blob/d4d2468706530082d57733776835593e2c107497/docsdata/content/__nodes/node_render_sprite_sheet.md).

### Inferences

**A. Основной кандидат — текстуры для игровой сцены.**

Пользователь выбирает размер и палитру, настраивает масштаб/детальность/контраст и seed, видит пиксельный результат и повторение рядом, сохраняет рецепт, получает несколько вариантов камня/земли/водной поверхности, применяет выбранный вариант к существующему слою и дорабатывает вручную. Затем открывает сохранённый рецепт для другого документа и экспортирует PNG. Для пользователя, который не художник, разумны готовые стартовые рецепты с небольшим набором понятных параметров плюс доступ к самим связям.

Предлагаемые критерии готовности: изменение параметра имеет заметный объяснимый результат; одинаковые исходные параметры и seed воспроизводят результат в заявленной области поддержки; предпросмотр не портит документ; применение — одна отменяемая правка; рецепт повторно открывается и применяется; пространственный шов проверяется явно; экспортированные пиксели совпадают с принятым результатом. Это сильнее демонстрации «есть Noise node».

**B. Stretch — зацикленная вода.**

Один подготовленный рецепт выдаёт ограниченный диапазон кадров: пользователь меняет скорость/амплитуду, палитру, seed и размер; видит анимацию, применяет результат к заранее созданным кадрам и экспортирует спрайтшит/GIF/APNG существующим workflow Pixprite. Приёмка должна отдельно проверять пространственные края и переход последнего кадра к первому. Не обещать, что произвольный шум, частицы или симуляция автоматически становятся seamless от галочки Loop. Для первого stretch достаточно одного достоверно периодического рецепта.

**C. Следующий сильный кандидат — эффект из нарисованного элемента.**

Пользователь рисует маленькую искру/лист, применяет подготовленный рецепт распределения и движения, меняет количество/направление/цвет и получает короткий игровой VFX. Демонстрационная ценность высокая: наглядно связывает ручной Pixprite и процедурную среду. Однако частицы с состоянием и произвольной петлёй могут значительно увеличить объём; для 0.0.10 это вторичный кандидат, а не скрытая обязательная зависимость.

**D. Позже — растительность и большие системы.**

Деревья, анимированный рост, трава по маске, дождь с кругами и взрывы хорошо показывают перспективу. Для первого этапа можно сохранять их как рецепты/семейства будущих возможностей. Полная физика жидкости/дыма, feedback, 3D, скелетная анимация и headless-производство — отдельные этапы.

**Рекомендуемый порядок продуктовых результатов, без выбора реализации:**

1. Рецепт с внешними параметрами, seed, предпросмотром, сохранением и применением к одному существующему слою/кадру.
2. Один законченный генератор текстуры плюс несколько визуально разных собственных стартовых рецептов.
3. Повторное применение в другом документе, ручная доработка, undo/redo, точный экспорт.
4. При достаточной готовности — один контролируемый анимированный рецепт с проверенным циклом и экспортом игрового ассета.
5. Для itch.io — собственный демонстрационный проект и короткое видео «параметры → варианты → применение → ручная правка → экспорт».

### Gaps

- Это предварительная продуктовая рекомендация. Пользовательский спрос, объём разработки и удобство предложенных параметров ещё надо проверить на прототипе Pixprite.
- Никакой конкретный движок графа, вычислитель, технология рендера, формат сериализации, кеш или UI-библиотека этим исследованием не утверждены.
- Чужие графы/спрайты/код из `.tmp/references/Pixel-Composer` используются для чтения. В продукт и демонстрационные ассеты Pixprite они не переносились.
